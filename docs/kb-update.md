# Обновление базы знаний и переиндексация

Инструкция для методиста и разработчика: как устроены файлы базы знаний, как добавить лекцию, методичку, вопрос
FAQ или дополнительный ресурс и как пересобрать индекс — локально и на сервере.

Коротко:

```bash
# 1. Правите или добавляете файлы в data/kb/
# 2. Пересобираете индекс
python -m curator.ingest
# 3. Проверяете, что индекс совпадает с базой, и прогоняете тесты (они проверяют формат данных)
python -m curator.ingest --check
bash check.sh --no-sync
# 4. На сервер — скриптом выкладки (раздел 10)
```

Команды выполняются из корня проекта (`ai-curator/`) в окружении проекта (`.venv`, см. README).

## 1. Что где лежит и что требует переиндексации

| Что | Файл | Пересобрать индекс? | Перезапустить приложение? |
|---|---|---|---|
| Лекции | `data/kb/module-N/lecture-N.M.md` | да | нет: приложение подхватит новую коллекцию само |
| Методички к заданиям | `data/kb/module-N/guide-N.md` | да | нет |
| FAQ | `data/kb/faq/faq.md` | да | нет |
| Обзор курса | `data/kb/course/overview.md` | да | нет |
| Каталог дополнительных ресурсов | `data/resources/resources.csv` (раздел 7) | нет (не индексируется) | да |
| Few-shot пары | `data/fewshot/examples.yaml` | нет | да |
| Промпты и шаблоны ответов | `curator/prompts/*.md` | нет | да |
| Данные LMS | `data/lms/*.json` | нет | нет: читаются на каждый вопрос (см. [lms-stub.md](lms-stub.md)) |

Почему так: индекс Chroma строится только из `data/kb`. Остальное приложение загружает при сборке сервисов
и держит в памяти. Сервисы пересобираются сами, когда переиндексация переключила коллекцию в манифесте индекса;
правка каталога ресурсов, few-shot или промптов без переиндексации требует перезапуска Streamlit (локально —
остановить и снова `streamlit run app/streamlit_app.py`, на сервере — выкладка или `systemctl restart ai-curator`).

**Few-shot пары** (`data/fewshot/examples.yaml`). Поля пары перечислены в шапке файла: `id`, `intent`, `level`,
`question`, `sources`, `good_answer`, `bad_answer`, `why_bad` и необязательное `tags` — условия, при которых пара
уместна. Поле `sources` идёт в промпт строкой «Материалы примера: [1] …; [2] …» (блок `fewshot_item`
в `curator/prompts/context.md`): модель видит, на что опираются номера в хорошем ответе, поэтому метки должны
совпадать с тем, на что ссылается `good_answer`. Код знает одно условие — `revision` (у студента задание на доработке): пара с ним идёт в промпт только при
этом условии и тогда первой в своём сценарии. Пара с условием, которого код не знает, в промпт не попадёт никогда.
Тест `tests/test_data_contract.py` требует не меньше 16 пар и все восемь сценариев; как пары выбираются для промпта —
[architecture.md](architecture.md), раздел 3.5.

## 2. Формат файла базы знаний

Файлы — markdown в UTF-8. Код читает все `*.md` внутри `data/kb` (в любых подпапках), но порядок папок
`module-N/`, `faq/`, `course/` лучше сохранять. Каждый файл начинается с YAML front-matter между строками `---`:

```yaml
---
id: L2.2
title: "Фильтрация, сортировка, пропуски"
module: 2
topic: pandas-filtering
resource_type: lecture
level: all
---
```

| Ключ | Обязателен | Значение |
|---|---|---|
| `id` | да | уникальный во всей базе: `L<модуль>.<номер>` для лекции, `guide-<модуль>` для методички, `faq`, `course-overview`; повтор id — ошибка |
| `title` | да | название; в подписи источника: «Лекция L2.2 «…»», методичка — по названию |
| `module` | да | целое 0-4; `0` — общие документы (FAQ, обзор курса), они проходят фильтр любого модуля |
| `topic` | да | короткий slug темы латиницей (`pandas-filtering`); по нему работают фильтр поиска, каталог ресурсов и аналитика по темам |
| `resource_type` | да | `lecture`, `guide`, `faq` или `overview` — фильтр по типу ресурса |
| `level` | да | `beginner`, `advanced` или `all` |

Заголовок `#` — название документа. Разделы — заголовки `##`; подразделы `###` входят в свой раздел. Текст до первого
`##` — вступление. Код в блоках ```` ```python ```` сохраняет отступы при нарезке.

### Вид раздела по заголовку

Код определяет вид раздела по словам в заголовке `##` (первое совпадение, регистр не важен):

| Слова в заголовке | Вид | Для чего код ищет такой раздел |
|---|---|---|
| «Если сложно» | `if_hard`, уровень beginner | рекомендация начинающему: что повторить |
| «Для продвинутых» | `advanced`, уровень advanced | рекомендация продвинутому: куда углубиться |
| «Частые ошибки», «Типичные ошибки» | `mistakes` | сценарий «мне трудно» опирается на него |
| «Критери…» | `criteria` | отказ в оценке цитирует критерии методички |
| «Как сдать», «Сдача» | `submission` | — |
| «Дедлайн», «Срок» | `deadline` | — |
| «Цель», «Шаги», «Данные» | `goal`, `steps`, `data` | вопрос о задании модуля: код сам кладёт эти разделы методички в материалы |
| прочие | `content` | — |

Вид записывается в метаданные фрагмента (`section_kind`); у «Если сложно» и «Для продвинутых» уровень раздела
заменяет уровень документа.

Обязательные разделы (их проверяют тесты `tests/test_data_contract.py`):

- у каждой лекции — «Частые ошибки», «Если сложно», «Для продвинутых»;
- у каждого модуля 1-4 — методичка с разделом «Критерии оценки».

В обзоре курса раздел со словом «куратор» в заголовке («ИИ-куратор») — на него ссылается ответ на вопрос не по курсу.

### На какие заголовки опирается код

Часть материалов код кладёт в ответ сам, без векторного поиска, — находит их по заголовку или виду раздела
([architecture.md](architecture.md), разделы 5.2 и 6.8). Если переименовать такой раздел, ответы станут хуже,
а тесты этого не заметят: `tests/test_data_contract.py` проверяет только обязательные разделы выше, наличие тем
FAQ `grading`, `extensions`, `recordings` и то, что срок появления записи в FAQ темы `recordings` («в течение
24 часов») совпадает с `RECORDING_DELAY` в `curator/lms.py`. Поэтому при правке держите формат:

| Где | Заголовок | Что делает код |
|---|---|---|
| обзор курса | `## Модуль N. …` — начинается со слова «Модуль» и номера: «Модуль 2. Pandas: работа с таблицами (16-29 ноября 2026)» | на вопрос о модуле целиком («что изучаем во втором модуле?») кладёт этот раздел в материалы вместе с данными LMS по модулю |
| обзор курса | раздел со словом «куратор» | ссылается на него в ответе на вопрос не по курсу |
| методичка | «Цель…», «Данные…», «Шаги…» (виды `goal`, `data`, `steps`) | на вопрос о задании модуля (в организационном вопросе и вопросе о сроках — на вопрос, что в задании сделать) кладёт в материалы первый раздел каждого вида |
| методичка | «Критери…» (вид `criteria`) | цитирует критерии в отказе об оценке |
| FAQ, тема `grading` | вопросы со словом «доработк» в заголовке («Что значит статус «на доработку»?», «Сколько времени даётся на доработку?») | кладёт их в материалы, если у студента задание на доработке |
| FAQ, тема `deadlines` | вопрос со словами опоздания в заголовке — «не успе…», «опозда…», «просроч…», «после дедлайна», «дедлайн прошёл» («Что будет, если я не успею сдать ДЗ к дедлайну?») | кладёт его в материалы на вопрос об опоздании в сценариях `deadline` и `organizational`: что делать, если не успеваешь или дедлайн прошёл |
| FAQ, тема `recordings` | ответ «Будут ли записи вебинаров?» со словами «в течение 24 часов» | число должно совпадать с `RECORDING_DELAY`: по нему код считает срок появления записи в данных LMS (тест это проверяет) |
| FAQ, тема `schedule` | вопрос со словом «расписани» в заголовке («Может ли ИИ-куратор перенести вебинар или изменить расписание?») | цитирует в отказе на просьбу сдвинуть вебинар, разбор или защиту |
| FAQ, темы `grading`, `extensions`, `recordings` | вопросы, которые цитируются в фиксированных ответах (раздел 3) | цитирует в отказе об оценке, отказе в переносе, отказе сдвинуть событие |

Раздел методички в материалах ограничен 3500 знаками (`GUIDE_SECTION_CHARS` в `curator/curator.py`; сейчас самый
длинный из таких разделов — «Данные» guide-4, 3438 знаков). Длиннее — блоки кода заменяются пометкой «(пример кода —
в методичке)», а если и этого мало, текст обрезается по абзацу. Без разделов «Цель», «Данные», «Шаги» методичка
работает, но вопрос о задании опирается только на поиск.

## 3. Формат FAQ

FAQ — один файл `data/kb/faq/faq.md` (`id: faq`, `module: 0`, `resource_type: faq`). Каждый вопрос — заголовок `##`,
сразу под ним строка с темой вопроса, ниже ответ:

```markdown
## Можно ли перенести дедлайн?
<!-- topic: extensions -->

Да, но только один раз за весь курс и максимум на 3 дня. …
```

Вопрос без строки `<!-- topic: … -->` и тема не из списка — ошибка индексации. Темы FAQ:

| Тема | Название в интерфейсе и отчёте |
|---|---|
| `deadlines` | Дедлайны |
| `extensions` | Перенос срока |
| `grading` | Оценки и проверка ДЗ |
| `certificate` | Сертификат |
| `recordings` | Записи вебинаров |
| `submission` | Сдача ДЗ |
| `support` | Поддержка и помощь |
| `schedule` | Расписание |
| `plagiarism` | Плагиат и самостоятельность |
| `access` | Доступ к курсу |
| `tools` | Инструменты: Python, Colab, Jupyter |

Фиксированные ответы опираются на темы FAQ: отказ в оценке цитирует вопрос темы `grading` «Кто ставит оценки…»,
отказ в переносе — вопрос темы `extensions` «Можно ли перенести дедлайн?», отказ на просьбу сдвинуть вебинар, разбор
или защиту — вопрос темы `schedule` со словом «расписани» в заголовке («Может ли ИИ-куратор перенести вебинар или
изменить расписание?»), а если вопросов темы `schedule` нет — вопрос темы `recordings` «Я пропустил вебинар…».
Если переименовать эти вопросы, отказ возьмёт первый вопрос той же темы. Ответ модели, когда у студента задание
на доработке, опирается на вопросы темы `grading` со словом «доработк» в заголовке: без такого слова правило
доработки в материалы не попадёт. Ответ на вопрос об опоздании («не успею», «дедлайн прошёл») опирается на вопрос
темы `deadlines` со словами опоздания в заголовке («Что будет, если я не успею сдать ДЗ к дедлайну?»): без такого
вопроса в материалах инструкция сценария запрещает модели называть последствия опоздания (раньше она выводила их
из соседних вопросов о доработке). Если правило
о записях вебинаров изменится, поправьте вместе с FAQ и `RECORDING_DELAY` в `curator/lms.py`.

Новая тема FAQ — это правка кода: добавить slug в `FAQ_TOPICS` и название в `FAQ_TOPIC_LABELS` (`curator/kb.py`),
а для запасных правил анализа — ключевые слова в `_FAQ_TOPIC_KEYWORDS` (`curator/router.py`).

## 4. Как добавить лекцию

1. Создайте `data/kb/module-N/lecture-N.M.md` с front-matter (`id: LN.M`, `module: N`, `resource_type: lecture`,
   `level: all`, свой `topic`).
2. Напишите разделы `##`. Принятый в курсе объём — 700-1200 слов, с примерами кода; в конце обязательно «Частые
   ошибки», «Если сложно» (что повторить), «Для продвинутых» (что углубить).
3. Если тема новая, добавьте в `data/resources/resources.csv` 1-3 ресурса с этим `topic` (раздел 7), чтобы
   рекомендации по теме не были пустыми.
4. Пересоберите индекс (раздел 8) и проверьте ответом (раздел 11).

Новая лекция и её тема автоматически попадают в промпт анализа запроса (список модулей с лекциями и список тем
строятся из базы при запуске) и в список «Тема» слева в чате.

Ограничения кода:

- **Номер лекции в модуле — 1-3.** Регулярные выражения запасных правил и «модуль назван прямо» (`curator/router.py`:
  `L2.3`, «лекция 2.3») знают только номера 1-3. Лекцию `L2.4` модель анализа увидит в списке, но запасные правила
  её номер не распознают; чтобы распознавали, поправьте эти выражения.
- **Модули — 1-4.** Номер модуля зашит в схеме анализа запроса (`QueryAnalysis.module`), в `MODULE_TITLES`
  (`curator/config.py`) и в регулярных выражениях. Пятый модуль — это правка кода, а не только данных.
- **Ключевые слова темы** для запасных правил (`_TOPIC_KEYWORDS` в `curator/router.py`) не обновляются сами:
  без них при сбое модели анализа правила тему новой лекции не определят. Поиск при этом работает, а рекомендации
  возьмут тему из лучшего найденного фрагмента.

## 5. Как добавить методичку

1. Создайте `data/kb/module-N/guide-N.md` с front-matter (`id: guide-N`, `module: N`, `resource_type: guide`).
   Название по образцу: «Методичка к ДЗ hw2 «Продажи кофейни»».
2. Разделы по образцу курса: «Цель ДЗ», «Данные», «Шаги», «Критерии оценки» (с баллами), «Частые ошибки», «Как
   сдать», «Дедлайн и перенос». Первые три код кладёт в материалы на вопрос о задании, критерии — в отказ
   об оценке (раздел 2, «На какие заголовки опирается код»).
3. Если методичка относится к заданию LMS, её `id` должен стоять в поле `guide_id` задания в
   `data/lms/assignments.json` (тест проверяет, что такой документ есть в базе).
4. Пересоберите индекс.

На один модуль — одна методичка: отказ в оценке берёт критерии из первой методички модуля.

## 6. Как добавить вопрос FAQ

1. Добавьте в `data/kb/faq/faq.md` заголовок `## Вопрос?`, под ним `<!-- topic: … -->` с темой из таблицы раздела 3,
   ниже ответ. Правила курса формулируйте так же, как в методичках и обзоре курса: противоречия база не ловит,
   и куратор процитирует оба варианта.
2. Пересоберите индекс.

Каждый вопрос FAQ — отдельный раздел и обычно один фрагмент индекса; в блоке «Источники» он подписан текстом
вопроса: «FAQ: «Можно ли перенести дедлайн?»».

## 7. Как добавить дополнительный ресурс

Каталог дополнительных ресурсов — `data/resources/resources.csv` (UTF-8, первая строка — заголовок). Он не
индексируется: ресурсы выбирает код по уровню, модулю и теме, модель только объясняет выбор и берёт адрес из
каталога ([architecture.md](architecture.md), раздел 6.7). Одна строка — один ресурс:

```csv
id,title,url,module,topic,level,kind,minutes,description
res-35,"pandas: Merge, join, concatenate",https://pandas.pydata.org/docs/user_guide/merging.html,2,pandas-groupby,advanced,docs,,"Как объединять таблицы: merge, join, concat. На английском."
```

| Колонка | Значение |
|---|---|
| `id` | уникальный: `res-NN` по порядку (на него ссылаются наборы оценки — `expected_sources`) |
| `title` | название, как его увидит студент; в блоке «Источники» — ссылкой на `url` |
| `url` | только реальный публичный адрес `https://…` (документация, учебник, курс); придуманных и платных адресов не ставить |
| `module` | `1`-`4`; `0` — общий ресурс (установка среды, Colab), подходит любому модулю |
| `topic` | slug темы из базы знаний (тема лекции, методички или FAQ: `pandas-filtering`, `tools`); совпадение темы с вопросом — самое сильное в выборе (+4 к очкам) |
| `level` | `beginner`, `advanced` или `all`; ресурс чужого уровня студенту не предлагается |
| `kind` | `docs`, `tutorial`, `article`, `course`, `book`, `catalog`, `video` или `practice` (`KIND_LABELS` в `curator/recommender.py`; в ответе — «документация», «учебник» и т. д.) |
| `minutes` | реальная длительность чтения или прохождения в минутах; попадает в ответ как «~N мин», и выходная проверка рекомендаций пропускает только это число. Не знаете — оставьте пустым |
| `description` | 1-2 предложения: что внутри и на каком языке |

Поле с запятой берётся в кавычки, как в примере. После правки каталога переиндексация не нужна, но нужен перезапуск
приложения (раздел 1); на сервере — выкладка (раздел 10). Тесты `tests/test_data_contract.py` проверяют, что адреса
`https://`, `level`, `kind`, `module` и `topic` из допустимых значений и `id` не повторяются.

## 8. Переиндексация

```bash
python -m curator.ingest           # полная пересборка индекса
python -m curator.ingest --check   # только сверить индекс с data/kb
```

Нужен `OPENAI_API_KEY` в `.env` (для `--check` — не нужен). Что делает `python -m curator.ingest`:

1. Разбирает всю базу в строгом режиме: первая ошибка формата останавливает сборку до того, как тратить деньги
   на эмбеддинги.
2. Режет документы на фрагменты: разделы `##`, длинные — по 1200 знаков с перекрытием 150; в начало фрагмента
   добавляется «Название. Раздел»; у фрагмента метаданные `doc_id`, `title`, `module`, `topic`, `resource_type`,
   `level`, `section` (подробно — [architecture.md](architecture.md), раздел 6).
3. Считает эмбеддинги `text-embedding-3-large` пачками по 64 и пишет их в новую коллекцию Chroma
   `kb-<дата>-<время>-<хвост>` рядом со старой.
4. Только когда все фрагменты записаны, переключает манифест `manifest.json` на новую коллекцию; затем удаляет
   старые коллекции и их файлы. Если эмбеддинги упали на середине, рабочий индекс остаётся прежним.

Пересборка всегда полная: база маленькая, а частичное обновление легко оставляет в индексе фрагменты удалённого
раздела. Итог печатается одной строкой:

```
Готово за … с: 18 документов, 252 фрагментов (faq: 63, guide: 47, lecture: 123, overview: 19); коллекция kb-20261112-090720-ba02c7 в …
```

`--check` сверяет манифест индекса с файлами базы (хеши SHA-256), моделью эмбеддингов и настройками нарезки:

| Результат | Сообщение | Код выхода |
|---|---|---|
| индекс актуален | «Индекс актуален: 252 фрагментов, собран 2026-11-12T09:07:20+03:00» | 0 |
| база правилась после сборки | «Индекс устарел — после сборки в базе знаний изменены: …; добавлены: …; удалены: …» | 1 |
| другая модель эмбеддингов или `CHUNK_SIZE` / `CHUNK_OVERLAP` | «Индекс собран моделью …» / «Поменялись настройки нарезки …» | 1 |
| индекса нет | «Индекса нет в …. Соберите его: python -m curator.ingest» | 1 |
| путь к индексу не ASCII на Windows | текст с подсказкой про `CURATOR_INDEX_DIR` | 2 |

Пересобирать индекс нужно после любой правки `data/kb`, после смены `EMBED_MODEL`, `CHUNK_SIZE` или `CHUNK_OVERLAP`.

**Что видит приложение.** Если база правилась, а индекс нет, работающий процесс правку не замечает: сервисы
собраны при запуске и пересобираются только при смене коллекции индекса. После перезапуска приложения чат работает
по старому индексу и показывает вверху предупреждение «Индекс устарел…», а фиксированные ответы и рекомендации уже
берут разделы из новой базы. Актуальное состояние индекса без перезапуска — на странице «О проекте».
Если индекса нет или он собран другой моделью эмбеддингов, чат не запускается и показывает команду пересборки;
страницы «Аналитика» и «LMS» работают. Файл с ошибкой формата приложение пропускает и показывает предупреждение,
а индексация на таком файле останавливается. Состояние индекса видно и на странице «О проекте».

## 9. Windows: путь к индексу

На Windows Chroma (hnswlib внутри неё) не пишет файлы индекса в папку с кириллицей в пути: сборка проходит, а при
следующем открытии Chroma падает с «Error loading hnsw index». Поэтому:

- если путь проекта ASCII, индекс лежит в `data/index` внутри репозитория (в git не хранится);
- если нет (как у папки «PEcf13. Учебный проект ИИ-куратор»), по умолчанию индекс лежит в
  `%LOCALAPPDATA%\ai-curator\index`, а если и это не ASCII — в `C:\ai-curator-index`; `ingest` напоминает об этом
  строкой «Индекс лежит вне репозитория: …»;
- свой путь задаётся переменной `CURATOR_INDEX_DIR` в `.env`, только ASCII:

```
CURATOR_INDEX_DIR=C:\ai-curator-index
```

Путь с не-ASCII символами в `CURATOR_INDEX_DIR` — ошибка с подсказкой (код выхода 2). На Linux ограничения нет.
Переменную нужно задать одинаково для `ingest` и для приложения: через `.env` это получается само.

## 10. Как обновить на сервере

Демо работает в контейнере под systemd (`deploy/`). Индекс на сервере не пересчитывается: его собирают локально,
и он едет вместе с кодом в архиве.

```bash
python -m curator.ingest                  # 1. пересобрать индекс локально
python -m curator.ingest --check          # 2. убедиться, что индекс совпадает с data/kb
DEPLOY_CT=<номер контейнера> bash deploy/deploy.sh   # 3. выложить (из Git Bash на Windows)
```

`deploy/deploy.sh`:

1. Ещё раз проверяет `ingest --check` и останавливается, если индекс не совпадает с базой.
2. Упаковывает код (`curator`, `app`, `tests`, `deploy`, `.streamlit`), документацию `docs/` (страница «О проекте»
   показывает схему `docs/diagram.svg`), код оценки `eval/*.py` (его импортируют тесты; наборы вопросов и прогоны
   не едут), `data/kb`, `data/lms`, `data/resources`, `data/fewshot` и индекс
   в архив, сверяет контрольную сумму после доставки.
3. Прогоняет тесты на отдельной копии в контейнере. Не прошли — рабочий код не трогается.
4. Заменяет код и данные в `/opt/ai-curator`, индекс — в `/var/lib/ai-curator/index`, ставит юниты и файл путей
   `/etc/ai-curator.paths.env` и перезапускает службы `ai-curator-lms` и `ai-curator`; до 60 с ждёт, пока обе
   ответят на проверку здоровья изнутри контейнера (`127.0.0.1:8502/health`, `127.0.0.1:8501/_stcore/health`;
   запросы делает `python3`, потому что `curl` в контейнере может не быть).
5. Проверяет сеть с хоста Proxmox по LAN-адресу контейнера — первый IPv4 из `pct exec <номер> -- hostname -I`,
   адрес в скрипте не зашит:
   - `http://<адрес>:8501/_stcore/health` должен ответить за 5 с — этим путём к Streamlit ходит cloudflared;
     не ответил — ошибка «туннель до службы не достучится»;
   - `<адрес>:8502` отвечать не должен: `curl` с кодом 7 (соединение отклонено) или 28 (нет ответа за 3 с) —
     порт закрыт, как и нужно; любой HTTP-ответ, даже 404, — ошибка «заглушка LMS отвечает по LAN-адресу»;
     другой код — ошибка «не удалось проверить».

**Сеть.** Streamlit слушает `0.0.0.0:8501`: cloudflared, который держит туннель `curator.optimum-ltd.com`, живёт
в соседнем контейнере (LXC 101, `192.168.95.103`) и подключается к службе по LAN — правило туннеля
`curator.optimum-ltd.com → http://192.168.95.173:8501` в `/etc/cloudflared/config.yml` LXC 101. Заголовкам
с адресом посетителя (ключ почасового лимита) куратор верит только от этого адреса: `CURATOR_TRUSTED_PROXIES` в
`deploy/ai-curator.paths.env` ([architecture.md](architecture.md), раздел 5.5). Если cloudflared переедет, адрес
нужно поправить там, иначе все посетители поделят один лимит на адрес прокси. Заглушка LMS слушает только
`127.0.0.1:8502`. `deploy.sh` проверяет путь с хоста Proxmox, а не из LXC 101, поэтому после первой выкладки или
переезда стоит проверить и настоящую цепочку: запрос из LXC 101 на `http://192.168.95.173:8501/_stcore/health`
и сам сайт.

Журнал (`/var/lib/ai-curator/journal.db`) и секреты (`/etc/ai-curator.env`: ключ OpenAI и соль кода сессии)
выкладка не трогает. Первый запуск на новом сервере — с файлом ключа:
`DEPLOY_CT=<номер контейнера> bash deploy/deploy.sh --secrets path/.env`.

Проверить индекс на самом сервере:

```bash
cd /opt/ai-curator && set -a && . /etc/ai-curator.paths.env && set +a
.venv/bin/python -m curator.ingest --check
```

## 11. Проверка после обновления

1. `bash check.sh --no-sync` — типы и тесты без сети. `tests/test_data_contract.py` читает настоящие `data/`
   и проверяет: база разбирается в строгом режиме, у лекций есть разделы для рекомендаций, у методичек — критерии,
   темы FAQ из списка и с русскими названиями, задания LMS ссылаются на методички из базы, каталог ресурсов
   и few-shot по формату.
2. Вопрос из терминала с отладкой — видно сценарий, модуль, тему, источники и строку поиска: итоговый фильтр,
   признак «ослаблен», каждый шаг поиска с числом найденного, сколько фрагментов выдачи оказалось вне запрошенного
   фильтра и лучшую близость:

   ```bash
   python -m curator ask "Чем loc отличается от iloc?" --debug
   python -m curator ask "Когда дедлайн второго ДЗ?" --student s3 --debug
   ```

   Например, строка поиска для «Что почитать, чтобы графики на слайдах защиты были читаемыми с проектора?»:

   ```
   поиск: без фильтра; ослаблен: True; шаги: модуль 3, тип lecture/guide, тема data-storytelling: 5 | модуль 3,
   тип lecture/guide: 5 | модуль 3: 5 | без фильтра: 5 | в выдаче вне фильтра «модуль 3, тип lecture/guide, тема
   data-storytelling»: 3 из 5; лучшая близость: 0.532
   ```

   Здесь анализ выбрал модуль 3, а три из пяти фрагментов выдачи — из лекции L4.3 «Защита проекта» (модуль 4):
   они ближе к вопросу, чем лекция модуля 3 даже с её прибавкой. «Ослаблен: True» значит, что в выдаче есть
   фрагменты вне фильтра; это не ошибка — фильтр анализа только приоритет ([architecture.md](architecture.md),
   раздел 6.6).

   Такой вопрос пишется в журнал с `source=demo` (ключ `--source` меняет метку).
3. Для заметных правок — прогон оценки (`eval/README.md`): тот же набор вопросов до и после правки.

## 12. Частые ошибки

| Сообщение | Что поправить |
|---|---|
| «нет YAML front-matter между строками «---» в начале файла» | front-matter должен быть первой строкой файла, ограничен `---` |
| «в front-matter нет ключей …» | добавить недостающие ключи из раздела 2 |
| «module должен быть числом 0-4» | `module: 2`, без кавычек |
| «resource_type … — допустимо lecture, guide, faq, overview» | исправить тип |
| «у вопроса «…» нет строки `<!-- topic: ... -->`» | добавить строку темы сразу под заголовком вопроса FAQ |
| «topic … у вопроса «…» — допустимо …» | взять тему из таблицы раздела 3 или добавить новую в код |
| «id … уже занят файлом …» | id документа должен быть уникальным |
| «Индекс устарел …» в чате | `python -m curator.ingest` |
| «Error loading hnsw index» на Windows | путь к индексу не ASCII: задать `CURATOR_INDEX_DIR` и пересобрать |
| «Нет OPENAI_API_KEY» | ключ в `.env` в корне проекта |
