### Ответ Y

Понимаю, что ошибки с преобразованием типов могут сбивать с толку, но это нормальная часть работы с данными.

Ошибка `ValueError: could not convert string to float: '94,50'` означает, что Python не может превратить строку `'94,50'` в число с плавающей точкой (`float`), потому что в числе стоит запятая вместо точки. В Python десятичная часть отделяется точкой, а не запятой.

Что делать:

1. В данных у вас цена кефира записана как строка `'94,50'` с запятой.
2. Перед преобразованием в число нужно заменить запятую на точку, чтобы получилось `'94.50'`.
3. После этого можно вызвать `float('94.50')`, и получится число 94.5.

Пример функции для преобразования строки в число с учётом запятой:

```python
def parse_number(text):
    """Преобразует строку с числом, где десятичный разделитель может быть запятой, в float.
    Если строка пустая, возвращает None."""
    if text == "":
        return None
    # Заменяем запятую на точку
    text = text.replace(",", ".")
    return float(text)

# Пример использования
price_str = "94,50"
price_float = parse_number(price_str)
print(price_float)  # Выведет 94.5
```

Проверьте, что в вашем коде для очистки данных есть такая замена, иначе Python не сможет преобразовать цену кефира и выдаст ошибку.

Если хотите проверить, сколько строк с пустыми или некорректными значениями у вас в данных, можно сделать так:

```python
for row in raw_rows:

        price = parse_number(row["price"])
    except ValueError:
        print("Ошибка в строке:", row)
```

## 12. Вопрос d11

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** Почему groupby('store')['revenue'].mean() даёт не средний чек? Как правильно посчитать средний чек и число чеков по точкам, желательно без apply

Ожидаемые пункты:
1. mean() по строкам даёт среднюю позицию (строку чека), а не средний чек: у одного order_id может быть несколько строк
2. Сначала сумма внутри чека: groupby(["store", "order_id"])["revenue"].sum(), затем среднее по чекам в разрезе store
3. Число чеков — nunique по order_id, а не count или size (они считают строки)
4. apply медленнее встроенных agg и transform; достаточно двух группировок или именованной агрегации
5. Уровень advanced: кратко, с терминами, без разжёвывания основ

Запрещено:
1. совет считать средний чек как groupby('store')['revenue'].mean()
2. оценка за hw2 или баллы

### Ответ X

`groupby('store')['revenue'].mean()` считает среднее значение выручки по строкам (позициям) в каждой точке, то есть среднюю позицию, а не средний чек.

**Почему?**  
В таблице одна строка — одна позиция заказа. Если у заказа несколько позиций, то среднее по строкам усредняет позиции, а не суммы заказов. Средний чек — это средняя сумма заказа, то есть сначала нужно сложить выручку по всем позициям внутри каждого заказа, а потом усреднить эти суммы по заказам.

---

**Как правильно посчитать средний чек и число чеков по точкам без `apply`:**

```python
# Суммируем выручку внутри каждого заказа в каждой точке
checks = sales.groupby(['store', 'order_id'], as_index=False)['revenue'].sum()

# Средний чек по точкам — среднее суммы заказов
avg_check = checks.groupby('store')['revenue'].mean()

# Число чеков по точкам — число уникальных заказов
num_checks = sales.groupby('store')['order_id'].nunique()

print(avg_check)
print(num_checks)
```

- `checks` — таблица с суммой выручки по каждому заказу в каждой точке.
- `avg_check` — средний чек по точкам.
- `num_checks` — число уникальных заказов (чеков) по точкам.

Так вы получите правильные метрики без использования `apply`.

### Ответ Y

`groupby('store')['revenue'].mean()` считает среднее значение выручки по строкам таблицы, то есть усредняет позиции заказов, а не сами заказы. Это не средний чек, потому что один заказ может состоять из нескольких строк (позиций), и нужно сначала сложить выручку внутри каждого заказа, а потом усреднить по заказам.

Правильный способ посчитать средний чек по точкам — сначала сгруппировать по `store` и `order_id`, сложить выручку внутри заказа, а потом усреднить по заказам в каждой точке:

```python
checks = sales.groupby(['store', 'order_id'], as_index=False)['revenue'].sum()
avg_check = checks.groupby('store')['revenue'].mean()
```

Число чеков (уникальных заказов) по точкам считается через `nunique` по `order_id`:

```python
orders_count = sales.groupby('store')['order_id'].nunique()
```

Так вы получите средний чек и число заказов по каждой точке без использования `apply`,.

Подробнее эта тема разбирается в лекции L2.3 «Группировка и агрегация», раздел «Среднее по строкам и среднее по заказам» и «Несколько метрик: agg»,.

Если хотите сделать сразу обе метрики в одной таблице:

```python
summary = checks.groupby('store').agg(
    avg_check=('revenue', 'mean'),
    orders=('order_id', 'nunique')
)
```

Обратите внимание, что `nunique` по `order_id` в исходном `sales` тоже даст число заказов, но для среднего чека нужно сначала агрегировать по заказам, чтобы не усреднять позиции, а заказы целиком,.

Для углубления рекомендую раздел «Несколько метрик: agg» в L2.3 и документацию pandas по groupby с именованными агрегатами,.


Но если ты хочешь **использовать результат дальше в программе** — например, сложить с другим числом или сохранить в переменную — `print` не поможет.

- `print` — просто показывает на экране, но не даёт результат для программы.

## 25. Вопрос d14

Условия: уровень auto, студент —, модуль 3; ответ в материалах есть.

**Вопрос:** что за чорная палочка на столбиках в сиборне barplot? и почему выручка по категориям получается какая-то маленькая

Ожидаемые пункты:
1. По умолчанию sns.barplot считает среднее по категории, а не сумму — поэтому «выручка» маленькая
2. Чёрная черта — 95-процентный доверительный интервал, полученный бутстрепом
3. Для выручки нужен estimator="sum", а интервал убирается параметром errorbar=None

Запрещено:
1. утверждение, что barplot по умолчанию показывает сумму
2. утверждение, что черта — это стандартное отклонение или ошибка данных

### Ответ X

Добрый день! Ваш вопрос про чёрную палочку на столбиках и маленькие значения выручки в `sns.barplot` очень типичный.

1. **Чёрная палочка** — это 95-процентный доверительный интервал (ДИ), который показывает, насколько надёжна оценка среднего значения. Он считается с помощью бутстрепа — метода случайных повторных выборок из данных. Если палочка короткая, значит среднее оценено точно, если длинная — есть большая неопределённость.

2. **Почему выручка маленькая?** По умолчанию `sns.barplot` не считает сумму, а показывает **среднее** значение по каждой категории. Поэтому вы видите средний чек, а не общую выручку. Чтобы получить сумму, нужно явно указать параметр `estimator="sum"`.

Вот пример, как построить график с суммой выручки по категориям и убрать доверительный интервал:

```python
import matplotlib.pyplot as plt
import seaborn as sns

order = orders.groupby("category")["amount"].sum().sort_values(ascending=False).index

fig, ax = plt.subplots(figsize=(7, 4))
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None,
            order=order, color="tab:blue", ax=ax)
ax.set(xlabel="Выручка, руб.", ylabel="")
plt.show()
```

- `estimator="sum"` — считает сумму вместо среднего.
- `errorbar=None` — отключает чёрные палочки с доверительным интервалом.
- `order=order` — сортирует категории по убыванию выручки, чтобы график был удобнее для восприятия.

Если хотите подробнее понять, как выбирать тип графика и что показывают разные виды, рекомендую раздел «Как выбрать тип графика» в лекции L3.2.

Если тема доверительных интервалов и агрегирования пока непонятна, можно повторить раздел «Что показывает barplot: среднее, а не сумму» в лекции L3.2.

Если что-то осталось неясным, спрашивайте!

### Ответ Y

Чёрная палочка на столбиках в `sns.barplot` — это 95-процентный доверительный интервал (confidence interval), который по умолчанию строится с помощью бутстрепа. Она показывает, насколько надёжна оценка среднего значения для каждой категории.

Если вы строите график выручки по категориям с помощью `sns.barplot` без дополнительных параметров, то по умолчанию он считает **среднее значение** (например, средний чек), а не сумму выручки. Поэтому суммы кажутся маленькими.

Чтобы получить именно сумму выручки по категориям, нужно указать параметр `estimator="sum"` и отключить доверительный интервал, если он не нужен, например:

```python
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None)
```

Это покажет сумму выручки по каждой категории, а не среднее.

## 31. Вопрос d12

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** loc vs iloc: почему df.loc[0:2] возвращает 3 строки, а df.iloc[0:2] две? И отдельно: ловлю SettingWithCopyWarning на orders[orders['qty'] > 3]['price'] = 0, а исходная таблица не меняется

Ожидаемые пункты:
1. loc выбирает по меткам и включает правую границу, iloc — по позициям и правую границу не включает (как срез списка)
2. orders[mask]['price'] = 0 — цепочечное присваивание: меняется временная копия, исходная таблица остаётся прежней
3. Правильно: orders.loc[mask, "price"] = 0; если отфильтрованную часть потом меняют — subset = orders[mask].copy()
4. Copy-on-Write: в pandas 2.x включается опцией mode.copy_on_write, в pandas 3.0 работает по умолчанию
5. Уровень advanced: термины, нюансы, ссылка на документацию (например, res-18 «pandas: индексация и выбор данных»)

Запрещено:
1. совет просто подавить предупреждение как решение
2. утверждение, что loc и iloc одинаково обрабатывают правую границу

### Ответ X

Понимаю, что такие детали могут сбивать с толку — это нормальная часть работы с pandas.

1. По `loc` и `iloc`:  
`loc` выбирает по меткам индекса, и при срезе правая граница включена, поэтому `df.loc[0:2]` вернёт строки с индексами 0, 1 и 2 — всего 3 строки.  
`iloc` выбирает по позициям, и правая граница при срезе не включается, поэтому `df.iloc[0:2]` вернёт строки с позициями 0 и 1 — всего 2 строки.

2. По `SettingWithCopyWarning` и присваиванию:  
`orders[orders['qty'] > 3]['price'] = 0` создаёт временный срез (копию или view), а присваивание происходит в этом временном объекте, а не в исходном DataFrame. Поэтому исходная таблица не меняется, и pandas предупреждает, что вы, возможно, меняете копию, а не оригинал. Это предупреждение сигнализирует о потенциальной ошибке.  
Чтобы изменить значения в исходном DataFrame, используйте `.loc` с булевой маской:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Так вы явно указываете, что хотите изменить столбец `'price'` в тех строках, где `'qty' > 3`,.

Рекомендую повторить разделы про индексацию и выбор данных в L2.1, особенно про `loc` и `iloc`, а также про предупреждения SettingWithCopyWarning в разделе «Частые ошибки»,.

Если интересно, для продвинутых есть подробное руководство по индексации в документации pandas.

### Ответ Y

Разница между `loc` и `iloc` в срезах связана с тем, как они работают с индексами:

- `loc` выбирает по меткам индекса, и правая граница среза включается.  
  Например, `df.loc[0:2]` выберет строки с индексами 0, 1 и 2 — всего 3 строки.

- `iloc` выбирает по позициям (целочисленным индексам, как в списках), и правая граница среза НЕ включается.  
  Например, `df.iloc[0:2]` выберет строки на позициях 0 и 1 — всего 2 строки.

---

По поводу `SettingWithCopyWarning` и того, что изменения не сохраняются:

```python
orders[orders['qty'] > 3]['price'] = 0
```

- Здесь `orders[orders['qty'] > 3]` создаёт временную копию (срез), а не ссылку на исходный DataFrame.
- Присваивание в копию не меняет исходный DataFrame, поэтому изменения не сохраняются.
- Pandas предупреждает об этом через `SettingWithCopyWarning`.

Правильный способ изменить значения в исходном DataFrame — использовать `.loc` с булевой маской:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Так вы явно меняете столбец `'price'` в тех строках, где условие выполняется, и изменения сохранятся в `orders`.
