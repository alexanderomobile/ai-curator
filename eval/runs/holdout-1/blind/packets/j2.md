## 11. Вопрос h12

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** в чём разница между axes-level и figure-level функциями seaborn? catplot у меня игнорирует ax= и рисует отдельную картинку

Ожидаемые пункты:
1. функции уровня графика (histplot, boxplot, barplot, lineplot и др.) рисуют на одном Axes, принимают ax= и возвращают Axes, их можно разложить по сетке plt.subplots
2. функции уровня фигуры (displot, catplot, relplot, lmplot, pairplot, jointplot) создают свою фигуру, ax= не принимают и возвращают сетку FacetGrid (у pairplot — PairGrid, у jointplot — JointGrid)
3. catplot с ax= выдаёт UserWarning «catplot is a figure-level function and does not accept target axes»; для дашборда брать boxplot/barplot и другие функции уровня графика, а figure-level — для малых множеств через col= / row=

Запрещено:
1. утверждение, что catplot принимает ax=
2. совет просто подавить предупреждение без объяснения

### Ответ X

Функции seaborn делятся на два уровня:

1. **Axes-level** (уровень графика) — рисуют на одном объекте Axes, принимают параметр `ax=` и возвращают этот Axes. Примеры: `histplot`, `boxplot`, `barplot`, `lineplot` и др. Их удобно использовать, когда нужно собрать несколько графиков в одной фигуре через `plt.subplots`.

2. **Figure-level** (уровень фигуры) — создают собственную фигуру и не принимают параметр `ax=`. Вместо этого возвращают объект-сетку (`FacetGrid` или подобный), который управляет расположением подграфиков. Примеры: `catplot`, `displot`, `relplot`, `lmplot`, `pairplot`, `jointplot`. Они удобны для построения фасетных графиков с разбиением по категориям через `col=`, `row=`.

Поэтому `catplot` игнорирует `ax=` и рисует отдельную фигуру — это нормальное поведение для figure-level функций.

Если хотите управлять осью, используйте axes-level функции, например, `sns.boxplot` или `sns.barplot` вместо `catplot`.

Подробнее эта тема разбирается в лекции L3.2, раздел «Функции уровня графика и уровня фигуры».

Для углубления можно посмотреть официальный обзор функций seaborn в документации.

### Ответ Y

Разница между axes-level и figure-level функциями Seaborn в том, как они работают с объектами Matplotlib и как создают графики:

- **Axes-level функции** (например, `histplot`, `boxplot`, `scatterplot`, `barplot` и др.) рисуют график на уже существующем объекте `Axes`. Они принимают параметр `ax=`, на который можно передать конкретный график (ось) из `plt.subplots()`, и возвращают этот же объект `Axes`. Это удобно, если нужно собрать несколько графиков на одном холсте (figure), например, сделать дашборд.

- **Figure-level функции** (например, `catplot`, `displot`, `relplot`, `lmplot`, `pairplot`, `jointplot`) создают собственную новую фигуру (`Figure`) и сетку графиков (`FacetGrid` или подобные). Они **не принимают параметр `ax=`**, потому что сами управляют созданием фигуры и осей. Поэтому, если вы передаёте `ax=` в `catplot`, он его игнорирует и рисует отдельный график в новой фигуре.

Поэтому `catplot` всегда рисует отдельную картинку, а не на существующем `Axes`. Если хотите контролировать расположение графиков на фигуре, используйте axes-level функции и `plt.subplots()`. Если нужно быстро построить графики с разделением по категориям (`col=`, `row=`), удобно использовать figure-level функции, но они сами создают фигуру и оси.

## 26. Вопрос h10

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** чем отличаются size, count и nunique в agg? и почему средний чек у меня выходит сильно меньше, чем должен

Ожидаемые пункты:
1. size — число строк в группе, включая пропуски; count — число непустых значений столбца; nunique — число разных значений (например разных order_id)
2. groupby(...)['revenue'].mean() даёт среднюю позицию (строку), а не средний чек: сначала сумма внутри каждого чека (группировка по order_id), затем среднее по чекам
3. число чеков считают через nunique по order_id, а не через count или size

Запрещено:
1. утверждение, что count считает уникальные значения
2. средний чек как mean по строкам
3. развёрнутое объяснение для новичка с аналогиями вместо кратких терминов

### Ответ X

Разница между `size`, `count` и `nunique` в `agg`:

- **`size`** — количество строк в группе, включая пропуски (NaN). Просто считает, сколько строк попало в группу.
- **`count`** — количество непустых значений в указанном столбце. Если в столбце есть NaN, они не считаются.
- **`nunique`** — количество уникальных значений в столбце. Например, для подсчёта числа заказов нужно считать уникальные `order_id`.

---

Почему средний чек получается меньше, чем должен:

Средний чек — это средняя сумма заказа, а не средняя строка. Если у заказа несколько строк (позиций), нельзя просто взять среднее по строкам `revenue`. Нужно сначала сложить выручку внутри каждого заказа (сгруппировать по `order_id` и сложить `revenue`), а потом усреднять по заказам.

Пример правильного расчёта среднего чека:

```python
checks = sales.groupby(["city", "order_id"], as_index=False)["revenue"].sum()
avg_check = checks.groupby("city")["revenue"].mean()
print(avg_check)
```

Если взять просто `sales.groupby("city")["revenue"].mean()`, то это средняя позиция (строка), а не средний чек.

---

Итого:

- Для числа заказов используйте `nunique` по `order_id`.
- Для среднего чека сначала суммируйте `revenue` по заказам, потом берите среднее.
- `size` и `count` считаются по строкам, не по заказам.

### Ответ Y

В `agg` при группировке:

1. `size` — считает число строк в группе, включая пропуски.
2. `count` — считает непустые значения в указанном столбце.
3. `nunique` — считает количество уникальных значений (например, уникальных заказов).

Это важно, чтобы правильно считать число заказов: нужен `nunique` по `order_id`, а не `count` или `size` по строкам.

По среднему чеку: если взять просто `groupby("store")["revenue"].mean()`, то считается средняя позиция (строка), а не средний чек. Чтобы получить средний чек, нужно сначала сложить выручку по каждой позиции внутри заказа (`groupby(["city", "order_id"])["revenue"].sum()`), а потом усреднить по заказам (`groupby("city")["revenue"].mean()`).

Пример:

```python
checks = sales.groupby(["city", "order_id"], as_index=False)["revenue"].sum()
avg_check = checks.groupby("city")["revenue"].mean()
print(avg_check)
```

Так вы получите средний чек по городам, а не среднюю строку.

Для подробностей смотрите лекцию L2.3 «Группировка и агрегация», разделы «Несколько метрик: agg» и «Среднее по строкам и среднее по заказам».

**Вопрос:** зачем вообще нужен return, если есть print? запуталась совсем

Ожидаемые пункты:
1. print только показывает значение на экране, а return отдаёт результат из функции, чтобы его можно было использовать дальше (сложить, сохранить)
2. если return нет, функция возвращает None — из-за этого бывает TypeError: unsupported operand type(s) for +: 'NoneType' and 'float'
3. простой пример (например line_total(2, 89.9) → 179.8) и ссылка на L1.3 «Функции и модули»

Запрещено:
1. продвинутые темы (аннотации типов, yield, *args) вместо объяснения
2. сухой ответ в стиле advanced без примера

### Ответ X

Хороший вопрос! Вот главное отличие между `return` и `print` в функциях:

- `print` просто **показывает** значение на экране, но сама функция при этом возвращает `None`.
- `return` **отдаёт** значение из функции, чтобы его можно было дальше использовать в программе.

Пример:

```python
def show_total(total):
    print(f"Итого: {total:.2f}")

def get_total(quantity, price):
    return quantity * price

show_total(get_total(2, 89.9))  # напечатает: Итого: 179.80
```

Здесь `get_total` возвращает число, а `show_total` его печатает.

Если бы в `get_total` был `print` вместо `return`, то нельзя было бы использовать результат для дальнейших вычислений.

Итог:  
- `return` нужен, чтобы функция **возвращала значение** и его можно было использовать дальше.  
- `print` — только для вывода на экран, но результат функции при этом теряется.

Если хочешь, могу помочь с примерами!

### Ответ Y

Понимаю, путаница с `return` и `print` — частое дело в начале. Давайте разберёмся просто.

1. **`print` — это команда показать что-то на экране.**  
   Например, если написать:

   ```python
   print("Привет!")
   ```

   то в консоли увидите слово «Привет!». Но это только вывод, результат нельзя использовать дальше в программе.

2. **`return` — это команда вернуть значение из функции, чтобы его можно было использовать дальше.**  
   Например:

   ```python
   def add(a, b):
       return a + b

   result = add(2, 3)  # result теперь 5
   print(result)       # покажет 5
   ```

   Здесь функция `add` возвращает число 5, и мы можем сохранить его в переменную `result` и потом с ним работать.

3. **Почему `return` важен?**  
   Если функция только печатает (`print`), то она не отдаёт результат, и вы не сможете, например, сложить результаты нескольких вызовов или использовать их в других вычислениях.

4. **Пример из материалов:**

   ```python
   def line_total(quantity, price):
       """Вернуть стоимость позиции: количество, умноженное на цену."""
       return quantity * price

   print(line_total(2, 89.9))  # 179.8
   ```

   Здесь функция возвращает число, а `print` уже выводит его на экран. Если бы в функции был только `print`, то при попытке использовать результат дальше получился бы `None` — пустое значение.

## 39. Вопрос h14

Условия: уровень auto, студент s2, модуль —; ответ в материалах есть.

**Вопрос:** при изменении цен в отфильтрованной таблице вылезает SettingWithCopyWarning, и исходный df не меняется. как правильно?

Ожидаемые пункты:
1. цепочка присваиваний вида orders[mask]['price'] = 0 меняет временную копию, исходная таблица не меняется
2. правильно — orders.loc[mask, 'price'] = 0; если отфильтрованную часть потом меняют отдельно, сделать её копией через .copy()
3. нюанс: режим Copy-on-Write — в pandas 2.x включается pd.set_option('mode.copy_on_write', True), в pandas 3.0 работает по умолчанию

Запрещено:
1. совет подавить предупреждение через warnings без исправления кода
2. inplace=True как решение
3. объяснение для новичка с аналогиями вместо сути

### Ответ X

Правильно изменять значения в исходном DataFrame через `.loc` с булевой маской, а не через цепочку фильтраций. Например, вместо

```python
orders[orders["qty"] > 3]["price"] = 0  # вызывает SettingWithCopyWarning и не меняет исходный df
```

нужно писать

```python
orders.loc[orders["qty"] > 3, "price"] = 0  # правильно меняет исходный DataFrame
```

Если нужно работать с отфильтрованной частью отдельно и потом менять её, сделайте копию:

```python
subset = orders[orders["qty"] > 3].copy()
subset["price"] = 0  # изменения в копии, исходный df не меняется
```

Таким образом вы избегаете предупреждений и гарантируете изменение нужных данных.

### Ответ Y

Это классическая ошибка с цепочечной индексацией в pandas, описанная в разделе «Частые ошибки».

Проблема в том, что при записи вида

```python
filtered = df[df["qty"] > 3]
filtered["price"] = 0
```

`filtered` — это не всегда полноценная копия, а может быть временным объектом (view), и изменение в нём не затрагивает исходный `df`. pandas предупреждает об этом `SettingWithCopyWarning`.

Правильный способ — использовать `.loc` для изменения значений в исходном DataFrame по маске:

```python
df.loc[df["qty"] > 3, "price"] = 0
```

Если нужно работать с отфильтрованной частью отдельно, сделайте явную копию:

```python
subset = df[df["qty"] > 3].copy()
subset["price"] = 0
```

Так изменения в `subset` не повлияют на `df`, и предупреждения не будет.

Проверьте, что вы не меняете значения через цепочку индексации, а используете `.loc` или копию.

Для углубления рекомендую разделы «Булевы маски» и «Частые ошибки» лекции L2.2, а также документацию pandas по индексации и выбору данных.
