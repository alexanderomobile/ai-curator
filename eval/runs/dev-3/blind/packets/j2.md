## 5. Вопрос d09

Условия: уровень auto, студент s3, модуль —; ответ в материалах есть.

**Вопрос:** мне вернули hw1 на доработку, там у кефира ошибка ValueError: could not convert string to float: '94,50'. я не понимаю что это значит и что делать

1. В строке '94,50' дробная часть отделена запятой, а float() понимает только точку, поэтому возникает ValueError

Ошибка `ValueError: could not convert string to float: '94,50'` возникает потому, что в Python десятичная часть числа должна отделяться точкой, а не запятой. В вашем файле у кефира цена записана как строка `'94,50'` с запятой.

### Ответ Y

Понимаю, что ошибки с преобразованием типов могут сбивать с толку, но вы на правильном пути.

Ошибка `ValueError: could not convert string to float: '94,50'` означает, что Python не может превратить строку `'94,50'` в число с плавающей точкой (тип `float`), потому что в Python десятичная часть отделяется точкой, а не запятой.

В вашем случае цена у кефира записана как `'94,50'` с запятой, а не `'94.50'` с точкой. Поэтому нужно заменить запятую на точку перед преобразованием.

Что делать — шаги:

1. В функции, которая преобразует строки в числа (например, `parse_number`), добавьте замену запятой на точку:

```python
def parse_number(text):
    """Строку '89.90', '94,50' или '' превратить в float; для пустой строки вернуть None."""
    if text == "":
        return None
    # заменяем запятую на точку, чтобы float() сработал
    text = text.replace(",", ".")
    return float(text)
```

2. Используйте эту функцию для очистки значений `quantity` и `price` в ваших данных.

3. После этого ошибка должна исчезнуть, и цена кефира будет правильно считана.

Проверьте, что вы не просто выбросили строку с кефиром, а именно исправили цену — это важно для правильного подсчёта суммы покупок.

Если тема преобразования типов пока сложна, повторите раздел «Преобразование типов» в лекции L1.1, там всё подробно и с примерами.

## 12. Вопрос d11

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** Почему groupby('store')['revenue'].mean() даёт не средний чек? Как правильно посчитать средний чек и число чеков по точкам, желательно без apply

Ожидаемые пункты:
1. mean() по строкам даёт среднюю позицию (строку чека), а не средний чек: у одного order_id может быть несколько строк
2. Сначала сумма внутри чека: groupby(["store", "order_id"])["revenue"].sum(), затем среднее по чекам в разрезе store
3. Число чеков — nunique по order_id, а не count или size (они считают строки)
4. apply медленнее встроенных agg и transform; достаточно двух группировок или именованной агрегации
5. Уровень advanced: кратко, с терминами, без разжёвывания основ

Запрещено:
1. совет считать средний чек как groupby('store')['revenue'].mean()
2. оценка за hw2 или баллы

### Ответ X

`groupby('store')['revenue'].mean()` даёт среднее значение по строкам (позициям заказа), а не средний чек, потому что в данных одна строка — одна позиция заказа. Если у одного заказа несколько строк, то среднее по строкам не учитывает, что эти строки принадлежат одному заказу.

Правильный способ посчитать средний чек по точкам:

1. Сначала сгруппировать по `store` и `order_id`, чтобы сложить выручку внутри каждого заказа (чека).
2. Потом по точкам усреднить сумму заказов — это и будет средний чек.
3. Число чеков — это количество уникальных `order_id` в каждой точке.

Пример без `apply`:

```python
# Сумма выручки по каждому заказу в каждой точке
checks = sales.groupby(['store', 'order_id'], as_index=False)['revenue'].sum()

# Средний чек по точкам
avg_check = checks.groupby('store')['revenue'].mean()

# Число чеков по точкам
num_checks = checks.groupby('store')['order_id'].nunique()

print(avg_check)
print(num_checks)
```

Таким образом:

- `checks` — таблица с одним заказом на строку и суммой по нему.
- `avg_check` — средняя сумма заказа (чека) по каждой точке.
- `num_checks` — количество уникальных заказов (чеков) по каждой точке.

Это стандартный и эффективный способ без использования `apply`.

### Ответ Y

`groupby('store')['revenue'].mean()` считает среднее значение выручки по всем строкам (позициям) в магазине, а не средний чек. Это значит, что если один заказ состоит из нескольких строк, они считаются по отдельности, и среднее получается по позициям, а не по заказам.

Правильный способ посчитать средний чек по точкам:

1. Сначала сгруппировать по `store` и `order_id`, сложить выручку внутри каждого заказа (чека).
2. Затем сгруппировать по `store` и взять среднее по суммам заказов — это и будет средний чек.

Пример:

```python
checks = sales.groupby(['store', 'order_id'], as_index=False)['revenue'].sum()
avg_check = checks.groupby('store')['revenue'].mean()
```

Для подсчёта числа чеков по точкам используйте `nunique` по `order_id`:

```python
num_checks = sales.groupby('store')['order_id'].nunique()
```

Так вы получите число уникальных заказов в каждом магазине без `apply`.

Подробнее и с примерами — в лекции L2.3 «Группировка и агрегация», разделы «Среднее по строкам и среднее по заказам» и «Частые ошибки». Для углубления можно посмотреть документацию pandas по groupby.

## 25. Вопрос d14

Условия: уровень auto, студент —, модуль 3; ответ в материалах есть.

**Вопрос:** что за чорная палочка на столбиках в сиборне barplot? и почему выручка по категориям получается какая-то маленькая

Ожидаемые пункты:
1. По умолчанию sns.barplot считает среднее по категории, а не сумму — поэтому «выручка» маленькая
2. Чёрная черта — 95-процентный доверительный интервал, полученный бутстрепом
3. Для выручки нужен estimator="sum", а интервал убирается параметром errorbar=None

Запрещено:
1. утверждение, что barplot по умолчанию показывает сумму
2. утверждение, что черта — это стандартное отклонение или ошибка данных

### Ответ X

Такое поведение — обычное дело для `sns.barplot`. Вот почему:

1. Чёрная палочка — это 95-процентный доверительный интервал (confidence interval), который показывает, насколько надёжна оценка среднего значения. Он считается с помощью бутстрепа — метода статистической оценки.

2. По умолчанию `barplot` считает **среднее** значение по каждой категории, а не сумму. Поэтому если вы хотите увидеть общую выручку по категориям, а не средний чек, значения будут меньше, чем сумма.

Как исправить:

1. Чтобы получить сумму выручки по категориям, добавьте параметр `estimator="sum"`.

2. Если доверительный интервал не нужен, отключите его с помощью `errorbar=None`.

Пример кода:

```python
order = orders.groupby("category")["amount"].sum().sort_values(ascending=False).index

fig, ax = plt.subplots(figsize=(7, 4))
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None,
            order=order, color="tab:blue", ax=ax)
ax.set(xlabel="Выручка, руб.", ylabel="")
plt.show()
```

Так вы увидите сумму выручки по категориям без лишних элементов.

Если тема кажется сложной, рекомендую повторить разделы про `barplot` и агрегирование в лекции L3.2.

### Ответ Y

Чёрная палочка на столбиках в `sns.barplot` — это 95-процентный доверительный интервал (confidence interval), который по умолчанию строится с помощью бутстрепа. Она показывает, насколько надёжна оценка среднего значения для каждой категории.

Если вы строите график выручки по категориям с помощью `sns.barplot` без дополнительных параметров, то по умолчанию он считает **среднее** значение, а не сумму. Поэтому выручка получается маленькой — это средний чек, а не общая выручка.

Чтобы получить сумму выручки по категориям, нужно указать параметр `estimator=sum` и отключить доверительный интервал (`errorbar=None`), например:

```python
sns.barplot(data=orders, x="amount", y="category", estimator=sum, errorbar=None)
```

Или так:

```python
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None)
```

Тогда столбики покажут именно сумму выручки по каждой категории.

## 31. Вопрос d12

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** loc vs iloc: почему df.loc[0:2] возвращает 3 строки, а df.iloc[0:2] две? И отдельно: ловлю SettingWithCopyWarning на orders[orders['qty'] > 3]['price'] = 0, а исходная таблица не меняется

Ожидаемые пункты:
1. loc выбирает по меткам и включает правую границу, iloc — по позициям и правую границу не включает (как срез списка)
2. orders[mask]['price'] = 0 — цепочечное присваивание: меняется временная копия, исходная таблица остаётся прежней
3. Правильно: orders.loc[mask, "price"] = 0; если отфильтрованную часть потом меняют — subset = orders[mask].copy()
4. Copy-on-Write: в pandas 2.x включается опцией mode.copy_on_write, в pandas 3.0 работает по умолчанию
5. Уровень advanced: термины, нюансы, ссылка на документацию (например, res-18 «pandas: индексация и выбор данных»)

Запрещено:
1. совет просто подавить предупреждение как решение
2. утверждение, что loc и iloc одинаково обрабатывают правую границу

### Ответ X

Разница в `loc` и `iloc` связана с включением правой границы среза:

1. `loc[0:2]` выбирает строки с метками индекса от 0 до 2 включительно, то есть 3 строки (0, 1, 2).
2. `iloc[0:2]` выбирает строки по позициям 0 и 1, правая граница не включается, итого 2 строки.

Это частая причина путаницы.

---

По поводу `SettingWithCopyWarning` и того, что исходная таблица не меняется:

- Выражение `orders[orders['qty'] > 3]['price'] = 0` сначала создаёт временную копию отфильтрованной части, а потом пытается изменить её столбец. Изменения не затрагивают исходный DataFrame, и pandas предупреждает об этом.
- Правильный способ — использовать `.loc` для изменения по условию:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Так изменения применятся к исходной таблице.

---

Для проверки:

```python
mask = orders['qty'] > 3
print(mask.sum())  # сколько строк подходит под условие
orders.loc[mask, 'price'] = 0
```

---

Рекомендую повторить разделы про `loc` и `iloc` в L2.1 «Выбор строк и столбцов» и про фильтрацию с булевыми масками и частые ошибки в L2.2.

Если нужна помощь с другими ошибками, спрашивайте меня.

### Ответ Y

Разница между `loc` и `iloc` в срезах связана с тем, как они интерпретируют правую границу:

- `loc` выбирает по меткам индекса, и правая граница включена. Например, `df.loc[0:2]` выберет строки с индексами 0, 1 и 2 — всего 3 строки.
- `iloc` выбирает по позициям (целочисленным индексам), и правая граница не включена, как в обычных срезах Python. Поэтому `df.iloc[0:2]` выберет строки с позициями 0 и 1 — всего 2 строки.

---

По поводу предупреждения `SettingWithCopyWarning` и того, что исходная таблица не меняется при записи:

```python
orders[orders['qty'] > 3]['price'] = 0
```

Здесь `orders[orders['qty'] > 3]` создаёт временную копию (срез), а не ссылку на исходный DataFrame. Изменение в этой копии не влияет на оригинал, и pandas предупреждает об этом.

Правильный способ изменить значения в исходном DataFrame — использовать `.loc` с булевой маской:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Так вы явно указываете, что хотите изменить столбец `'price'` у строк, где `'qty' > 3`, в исходном DataFrame, и предупреждение не возникает.

### Ответ Y

Для продвинутых рекомендую лекцию L3.1 «Matplotlib: основы графиков» — там разбираются сложные компоновки с `subplot_mosaic` и `GridSpec`, форматирование осей через `matplotlib.ticker`, стили и временные настройки через `rcParams` и `plt.style.use()`. Также полезна официальная документация matplotlib — раздел Quick start guide и галерея примеров на matplotlib.org.
