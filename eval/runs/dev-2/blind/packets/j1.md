## 3. Вопрос d12

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** loc vs iloc: почему df.loc[0:2] возвращает 3 строки, а df.iloc[0:2] две? И отдельно: ловлю SettingWithCopyWarning на orders[orders['qty'] > 3]['price'] = 0, а исходная таблица не меняется

Ожидаемые пункты:
1. loc выбирает по меткам и включает правую границу, iloc — по позициям и правую границу не включает (как срез списка)
2. orders[mask]['price'] = 0 — цепочечное присваивание: меняется временная копия, исходная таблица остаётся прежней
3. Правильно: orders.loc[mask, "price"] = 0; если отфильтрованную часть потом меняют — subset = orders[mask].copy()
4. Copy-on-Write: в pandas 2.x включается опцией mode.copy_on_write, в pandas 3.0 работает по умолчанию
5. Уровень advanced: термины, нюансы, ссылка на документацию (например, res-18 «pandas: индексация и выбор данных»)

Запрещено:
1. совет просто подавить предупреждение как решение
2. утверждение, что loc и iloc одинаково обрабатывают правую границу

### Ответ X

Разница между `loc` и `iloc` в срезах связана с тем, что:

- `loc` выбирает по меткам индекса, и правая граница включена.  
  Например, `df.loc[0:2]` вернёт строки с индексами 0, 1 и 2 — всего 3 строки.

- `iloc` выбирает по позициям (целочисленным индексам), и правая граница НЕ включена.  
  Например, `df.iloc[0:2]` вернёт строки на позициях 0 и 1 — всего 2 строки.

---

По поводу `SettingWithCopyWarning` и того, что исходная таблица не меняется при записи:

```python
orders[orders['qty'] > 3]['price'] = 0
```

Здесь `orders[orders['qty'] > 3]` создаёт временную копию (срез), а не ссылку на исходный DataFrame.  
Изменение столбца `price` в этой копии не влияет на исходный `orders`. Pandas предупреждает об этом через `SettingWithCopyWarning`.

Правильный способ изменить значения в исходном DataFrame — использовать `.loc` с булевой маской:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Так вы явно указываете, что хотите изменить столбец `price` в строках, где `qty > 3`, в исходной таблице.  
Это не вызовет предупреждений и изменения сохранятся.

### Ответ Y

`loc` выбирает по меткам индекса, включая правую границу среза, поэтому `df.loc[0:2]` вернёт строки с индексами 0, 1 и 2 — всего 3 строки.

`iloc` выбирает по позициям, как в обычных срезах Python, где правая граница не включается, поэтому `df.iloc[0:2]` вернёт только первые две строки с позициями 0 и 1.

---

`SettingWithCopyWarning` возникает, когда вы пытаетесь изменить значения в результате фильтрации через цепочку индексации, например:

```python
orders[orders['qty'] > 3]['price'] = 0
```

Здесь `orders[orders['qty'] > 3]` создаёт временную копию, а не ссылку на исходный DataFrame, поэтому изменения не затрагивают исходную таблицу, и pandas предупреждает об этом.

Правильный способ — использовать `.loc` с маской, чтобы изменить значения напрямую в исходном DataFrame:

```python
orders.loc[orders['qty'] > 3, 'price'] = 0
```

Если хотите работать с подтаблицей, сделайте явную копию через `.copy()`:

```python
subset = orders[orders['qty'] > 3].copy()
subset['price'] = 0
```

```python
mask = orders['qty'] > 3
print(mask.sum())
```

2. Измените значения через `.loc` и проверьте, что в `orders` они изменились.

**Вопрос:** что за чорная палочка на столбиках в сиборне barplot? и почему выручка по категориям получается какая-то маленькая

Ожидаемые пункты:
1. По умолчанию sns.barplot считает среднее по категории, а не сумму — поэтому «выручка» маленькая
2. Чёрная черта — 95-процентный доверительный интервал, полученный бутстрепом
3. Для выручки нужен estimator="sum", а интервал убирается параметром errorbar=None

Запрещено:
1. утверждение, что barplot по умолчанию показывает сумму
2. утверждение, что черта — это стандартное отклонение или ошибка данных

### Ответ X

Чёрная палочка на столбиках в `sns.barplot` — это 95-процентный доверительный интервал (confidence interval), который по умолчанию строится с помощью бутстрепа. Она показывает, насколько надёжна оценка среднего значения для каждой категории.

Если вы строите график выручки по категориям и видите, что значения получаются маленькими, скорее всего, вы используете `sns.barplot` без параметра `estimator="sum"`. По умолчанию `barplot` считает **среднее** значение по каждой категории, а не сумму. Для выручки обычно нужна сумма, поэтому нужно указать `estimator="sum"`, чтобы получить правильные значения выручки.

Пример правильного вызова:

```python
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None)
```

Также параметр `errorbar=None` отключит отображение доверительного интервала, если он не нужен.

### Ответ Y

Такое бывает часто, и вы правильно заметили два важных момента.

1. Чёрная палочка на столбиках — это 95-процентный доверительный интервал, который seaborn рисует по умолчанию. Он показывает, насколько надёжна оценка среднего значения по каждой категории. Этот интервал считается с помощью метода бутстрепа — многократного случайного выбора подвыборок из данных.

2. Выручка по категориям кажется маленькой, потому что `sns.barplot` по умолчанию показывает **среднее** значение в каждой категории, а не сумму. Если вам нужна именно сумма выручки, нужно явно указать параметр `estimator="sum"` в функции `barplot`.

Как исправить:

1. Чтобы увидеть сумму выручки по категориям, добавьте `estimator="sum"`.

2. Чтобы убрать чёрные палочки с доверительными интервалами, добавьте `errorbar=None`.

Пример кода:

```python
import matplotlib.pyplot as plt
import seaborn as sns

order = orders.groupby("category")["amount"].sum().sort_values(ascending=False).index

fig, ax = plt.subplots(figsize=(7, 4))
sns.barplot(data=orders, x="amount", y="category", estimator="sum", errorbar=None,
            order=order, color="tab:blue", ax=ax)
ax.set(xlabel="Выручка, руб.", ylabel="")
plt.show()
```

Здесь `order` сортирует категории по убыванию суммы, чтобы столбцы шли в нужном порядке.

## 8. Вопрос d11

Условия: уровень advanced, студент —, модуль —; ответ в материалах есть.

**Вопрос:** Почему groupby('store')['revenue'].mean() даёт не средний чек? Как правильно посчитать средний чек и число чеков по точкам, желательно без apply

Ожидаемые пункты:
1. mean() по строкам даёт среднюю позицию (строку чека), а не средний чек: у одного order_id может быть несколько строк
2. Сначала сумма внутри чека: groupby(["store", "order_id"])["revenue"].sum(), затем среднее по чекам в разрезе store
3. Число чеков — nunique по order_id, а не count или size (они считают строки)
4. apply медленнее встроенных agg и transform; достаточно двух группировок или именованной агрегации
5. Уровень advanced: кратко, с терминами, без разжёвывания основ

Запрещено:
1. совет считать средний чек как groupby('store')['revenue'].mean()
2. оценка за hw2 или баллы

### Ответ X

`groupby('store')['revenue'].mean()` считает среднее значение выручки по всем строкам в каждой точке, то есть среднюю позицию заказа, а не средний чек. Это потому, что в данных одна строка — одна позиция заказа, а один заказ может содержать несколько строк.

Правильный способ посчитать средний чек по точкам — сначала сгруппировать по `store` и `order_id`, сложить выручку внутри каждого заказа, а потом усреднить по заказам в каждой точке. Для числа чеков по точкам используйте `nunique` по `order_id`.

Пример из лекции L2.3:

```python
checks = sales.groupby(["store", "order_id"], as_index=False)["revenue"].sum()
avg_check = checks.groupby("store")["revenue"].mean()
num_checks = sales.groupby("store")["order_id"].nunique()
```

`avg_check` — средний чек по точкам, `num_checks` — число чеков по точкам.

Нюансы:
- Не используйте `apply`, так как это медленнее и сложнее.
- `as_index=False` в первом groupby позволяет сохранить `store` как столбец для удобства.
- `nunique` считает уникальные заказы, а не строки.

Для углубления смотрите раздел «Среднее по строкам и среднее по заказам» в L2.3 и методичку hw2, раздел «Частые ошибки».

### Ответ Y

`groupby('store')['revenue'].mean()` даёт среднее значение по строкам (позициям заказа), а не средний чек, потому что в таблице одна строка — одна позиция заказа. Если у заказа несколько строк, то среднее по строкам не равно среднему по заказам.

Правильный способ посчитать средний чек по точкам:

1. Сначала сгруппировать по `store` и `order_id`, чтобы сложить выручку внутри каждого заказа (чека).
2. Затем по точкам взять среднее от суммы заказов — это и будет средний чек.
3. Для числа чеков посчитать количество уникальных `order_id` по каждой точке.

Пример без `apply`:

```python
# Сумма выручки внутри каждого заказа по точкам
checks = sales.groupby(['store', 'order_id'], as_index=False)['revenue'].sum()

# Средний чек по точкам
avg_check = checks.groupby('store')['revenue'].mean()

# Число чеков по точкам
num_checks = checks.groupby('store')['order_id'].nunique()

print(avg_check)
print(num_checks)
```

Таким образом:

- `checks` — таблица с одним заказом на строку и суммой по нему.
- `avg_check` — средняя сумма заказа по каждой точке.
- `num_checks` — число уникальных заказов (чеков) по каждой точке.

Это стандартный и эффективный способ без использования `apply`.

### Ответ X

Понимаю, давайте разберём проще и с примером.

**Что такое `groupby` в pandas?**

1. Представьте, что у вас есть таблица с заказами: в одном столбце — город, в другом — сумма заказа.
2. Вы хотите узнать, сколько всего денег принёс каждый город.
3. `groupby` — это способ разбить таблицу на части по городам, посчитать сумму для каждого города и собрать результаты в новую таблицу.

**Пример:**

```python
import pandas as pd

# Создаём таблицу с заказами
data = {
    "city": ["Москва", "Казань", "Москва", "Казань", "Питер"],

}
df = pd.DataFrame(data)

# Группируем по городу и считаем сумму выручки для каждого

```

```
Москва    250
Питер     300
Name: revenue, dtype: int64
```

- `groupby("city")` — разбивает таблицу на группы по городам.
- `["revenue"]` — выбирает столбец с суммами.
- `.sum()` — считает сумму в каждой группе.

Условия: уровень beginner, студент —, модуль —; ответ в материалах есть.

**Вопрос:** Не понимаю, зачем нужен return, если можно просто написать print? Объясните попроще, я первый раз программирую

Ожидаемые пункты:
1. print только показывает значение на экране, а return отдаёт результат из функции, чтобы его можно было использовать дальше (сложить, сохранить)
2. Если return нет, функция возвращает None, и следующий расчёт с её результатом падает (TypeError с 'NoneType')
3. Уровень beginner: простые слова, бытовая аналогия, короткий пример кода с комментариями, без нагромождения терминов
4. Ссылка на лекцию L1.3 «Функции и модули»

Запрещено:
1. утверждение, что print и return взаимозаменяемы
2. ответ из одних терминов без объяснения

### Ответ X

Понимаю, вопрос важный и часто вызывает сомнения у новичков.

1. Представьте, что функция — это как кухонный прибор: вы кладёте ингредиенты (параметры), он что-то делает и отдаёт результат.  
2. `return` — это как выход готового блюда из прибора, чтобы вы могли его использовать дальше: положить в тарелку, смешать с чем-то ещё, сохранить.  
3. `print` — просто показывает результат на экране, но не отдаёт его дальше программе. Это как если бы прибор только светился, но не отдавал еду.  

Пример:

```python
def line_total(quantity, price):
    return quantity * price  # функция возвращает число — стоимость

result = line_total(2, 89.9)  # сохраняем результат в переменную
print(result)                 # показываем результат: 179.8
```

Если заменить `return` на `print`:

```python
def line_total(quantity, price):
    print(quantity * price)  # только печатает, но не возвращает

result = line_total(2, 89.9)
print(result)  # здесь будет None — потому что функция ничего не вернула
```

То есть без `return` вы не сможете использовать результат функции в других вычислениях или сохранить его.

Если хотите, могу помочь с примерами и объяснить подробнее, как это работает.

### Ответ Y

Хороший вопрос! Вот простое объяснение.

`print` — это команда, которая просто показывает что-то на экране. Например:

```python
def show_total(total):
    print(f"Итого: {total}")
```

Если вызвать `show_total(100)`, на экране появится «Итого: 100». Но сама функция ничего не возвращает, то есть внутри программы результат не сохраняется.

А `return` — это команда, которая **возвращает значение из функции**, чтобы его можно было использовать дальше в программе. Например:

```python
def line_total(quantity, price):
    return quantity * price
```

Если вызвать `line_total(2, 50)`, функция вернёт число 100. Это число можно сохранить в переменную, сложить с другими числами, передать в другую функцию и так далее.

Пример:

```python
total = line_total(2, 50)  # total теперь 100
print(total + 20)          # напечатает 120
```

Если бы в `line_total` был только `print`, то нельзя было бы использовать результат дальше, только увидеть его на экране.

Итого:

- `print` — просто показывает результат, но не даёт его программе.
- `return` — даёт программе результат, чтобы с ним можно было работать.

Про сводные таблицы `pivot_table` рассказывали в лекции L2.3 «Группировка и агрегация». 

Там объясняли, что:

- `fill_value=0` ставит нули в ячейки, где данных нет (например, где продаж не было).
- `margins=True` добавляет итоговые строки и столбцы с суммами по всем группам (итоги).
- `margins_name="Итого"` задаёт название для итоговой строки и столбца.

### Ответ Y

Про сводные таблицы `pivot_table` рассказывается в лекции L2.3 «Группировка и агрегация», в разделе «Сводная таблица».

2. В разделе общего доступа выберите вариант «Все, у кого есть ссылка».
3. Установите роль «Читатель» (Viewer).
4. Скопируйте полученную ссылку.
5. Вставьте эту ссылку в форму сдачи задания в LMS.
6. Перед отправкой убедитесь, что ноутбук сохранён, все ячейки выполнены и результаты видны.
7. Рекомендуется проверить ссылку в режиме инкогнито, чтобы убедиться, что доступ открыт.

Если не открыть доступ по ссылке, преподаватель увидит «нет доступа».
