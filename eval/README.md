# Оценка куратора (eval/)

Стенд сравнивает полного куратора с наивным RAG на одном наборе вопросов: прогон обеих систем, детерминированные
проверки каждого ответа и слепая оценка LLM-судьями. Сеть нужна только прогону (`run_eval`); проверки, пакеты
судей и сводка их оценок работают без сети и без ключа.

| Файл | Что делает |
|---|---|
| `run_eval.py` | прогон набора через куратора и наивный RAG → `runs/<прогон>/answers.jsonl`, сводка |
| `baseline.py` | наивный RAG — точка сравнения |
| `checks.py` | детерминированные проверки ответов → `checks.jsonl`, `checks.md` |
| `blind.py` | слепые пакеты для судей и ключ раскрытия |
| `unblind.py` | сводка оценок судей по системам, сценариям и судьям |
| `dataset.py` | формат набора, проверка набора до первого платного вызова, общие помощники |
| `sample.json` | три вопроса для проверки самого стенда (не тестовый набор) |

Тестовые наборы вопросов пишутся отдельно от кода куратора и стенда.

## Наборы и прогоны

Наборы написали агенты Claude по материалам курса. Результаты — в README проекта, раздел
[«Результаты оценки»](../README.md#результаты-оценки).

| Набор | Вопросов | Прогоны | Назначение |
|---|---|---|---|
| `sets/dev.json` | 36 | `runs/dev-1`, `runs/dev-2`, `runs/dev-3` | рабочий: по разбору этих прогонов куратор дорабатывали три круга, поэтому цифры по нему завышены по построению |
| `sets/holdout.json` | 44 | `runs/holdout-1` | отложенный: написан отдельным агентом, по нему куратор не настраивали, прогнан один раз — главный результат |
| `sample.json` | 3 | `runs/sample-1` | проверка самого стенда |

Как прогнан отложенный набор (`holdout-1`):

- Набор — побайтная копия исходника, который до прогона лежал вне репозитория (sha256 `f6b7d6dc…cdf5` записан
  в `runs/holdout-1/meta.json`). `--dry-run` принял все 44 вопроса девяти сценариев: deadline 7, difficulty 7,
  material 8, recommendation 5, organizational 5, grading_request 3, schedule_change 3, off_topic 2, no_answer 4.
- Индекс тот же, что у dev-прогонов (`kb-20261112-090720-ba02c7`); `python -m curator.ingest --check` — актуален,
  пересборка не понадобилась.
- Код куратора и стенда заморожен. Один запуск, без дозапуска, с тем же `--now`, что у dev-прогонов:

  ```bash
  python -m eval.run_eval --set eval/sets/holdout.json --run holdout-1 --now 2026-11-12T12:00:00+03:00
  ```

  88 ответов (44 вопроса × 2 системы), у каждой пары одна попытка, ошибок, ответов в обход модели и обрезанных нет.
- Слепые пакеты для трёх судей j1-j3 (`eval.blind`): у каждого куратор стоит под X в 22 вопросах из 44. Судьи —
  агенты Claude. `eval.unblind holdout-1` свёл 132 оценки, раздел «Что не засчитано» пуст.
- Набор и прогон лежат в репозитории, а не вне его через `--out`, как советует раздел «Прогон». После публикации
  вопросы отложенного набора перестают быть закрытыми: следующую доработку честно проверять только на новом
  отложенном наборе.

## Быстрый старт

Из корня проекта (`ai-curator/`), окружение — `.venv` (см. `check.sh`), ключ — `OPENAI_API_KEY` в `.env`,
индекс собран (`python -m curator.ingest`).

```bash
python -m eval.run_eval --set eval/sample.json --dry-run          # набор, ключ, индекс — без вызовов API
python -m eval.run_eval --set eval/sample.json --run sample-1     # прогон: 3 вопроса × 2 системы ≈ $0.01
python -m eval.checks sample-1                                    # пересчитать проверки (прогон делает их сам)
python -m eval.blind sample-1 --judges j1,j2,j3                   # пакеты судьям
#   ... судьи пишут оценки в eval/runs/sample-1/blind/scores/<судья>.json ...
python -m eval.unblind sample-1                                   # раскрыть и свести
```

На Windows в консоли с кодировкой не UTF-8 перед командами: `set PYTHONIOENCODING=utf-8`
(в Git Bash — `export PYTHONIOENCODING=utf-8`).

## Формат набора

JSON-массив объектов. Ошибка в наборе останавливает прогон до первого вызова API: сообщение называет вопрос и поле.

```json
{"id": "d01", "question": "...", "intent": "deadline", "level": "auto", "student": "s1", "module": null,
 "history": [{"q": "предыдущий вопрос", "a": "кратко ответ"}], "answerable": true,
 "expected_points": ["факт, который обязан быть в верном ответе"],
 "forbidden": ["чего в ответе быть не должно"], "expected_sources": ["L2.3", "faq", "lms"], "notes": "что проверяет"}
```

| Поле | Значение |
|---|---|
| `id` | уникальная строка |
| `intent` | `deadline`, `difficulty`, `material`, `recommendation`, `organizational`, `grading_request`, `schedule_change`, `off_topic`, `no_answer` (ответа в материалах нет) |
| `level` | `auto` / `beginner` / `advanced` — выбор уровня в интерфейсе |
| `student` | `s1`…`s5` — демо-студент LMS, или `null` |
| `module` | 1-4 — модуль, выбранный в интерфейсе (у куратора — жёсткий фильтр поиска), обычно `null` |
| `history` | прошлые реплики для уточняющих вопросов, `[]` — без них |
| `answerable` | есть ли ответ в материалах курса |
| `expected_points`, `forbidden` | для судей (в пакете они пронумерованы с 1) |
| `expected_sources` | id документа или ресурса (`L2.3`, `guide-2`, `faq`, `course-overview`, `res-07`) или вид (`lms`, `faq`, `overview`); регистр не важен |

## Что сравнивается

| | Куратор | Наивный RAG |
|---|---|---|
| Индекс и эмбеддинги | Chroma, `text-embedding-3-large` | то же хранилище (тот же объект в одном прогоне) |
| Поиск | выбор в интерфейсе — жёсткий фильтр (ослабляется, если мало найдено), модуль, тип и тема из анализа запроса — приоритет при ранжировании (+0,05 к близости), порог близости | top-5 по тексту вопроса, без фильтров и порога |
| Материалы без поиска | данные LMS (в них и срок появления записи прошедшего вебинара), цель, данные и шаги методички на вопрос о задании, раздел обзора на вопрос о модуле, FAQ о доработке, FAQ о несданной в срок работе на вопрос об опоздании | нет |
| Анализ запроса, LMS, few-shot | есть | нет |
| Ограничения в коде (оценка, перенос, off-topic) и проверки ответа модели (обещание оценки или переноса, срок доработки, длительность в рекомендации) | есть | нет |
| Блок «Источники» | собирает код | нет |
| Модель ответа | `gpt-4.1-mini`, temperature 0.2, потолок 900 токенов | то же |
| Системный промпт | роль, уровень, сценарий, правила | «Ты помощник курса. Отвечай по контексту.» |
| Уровень, модуль, студент | параметры `ask()`, как в интерфейсе | неизвестны |
| history | память диалога (последние 2 реплики), в анализ и в промпт | прошлые реплики чата; поиск — по текущему вопросу |

Куратор собирается той же фабрикой, что и чат (`curator.factory.build_services`), с тремя отличиями:

- **«Сейчас» зафиксировано** параметром `--now` (по умолчанию `2026-11-12T12:00:00+03:00`, без зоны — МСК).
  Это `Settings.now_override` — тот же механизм, что переменная `CURATOR_NOW`, поэтому код куратора не менялся:
  дни до дедлайна, окно заявки на перенос и «сегодня» в промпте считаются от `--now`, прогоны воспроизводимы.
- **Журнал — свой файл** `runs/<прогон>/journal.db`; живой `data/journal.db` не трогается.
- **Записи помечены `source=eval`**, лимиты демо на них не действуют.

Каждая попытка ответа — новая сессия: `history` кладётся в память диалога как прошлые реплики, после ответа сессия
очищается.

## Прогон (`run_eval.py`)

```
python -m eval.run_eval --set НАБОР [--run ИМЯ] [--out ПАПКА] [--systems curator,baseline] [--now ISO]
                        [--workers 4] [--retries 3] [--only id1,id2] [--limit N] [--allow-stale-index] [--dry-run]
```

- Параллельно 4 запроса; при сбое API — до 3 повторов с паузой 2, 4, 8 с. Ответ, собранный куратором в обход
  модели (модель не ответила — список материалов; анализ запроса правилами из-за сбоя), тоже повторяется; если
  все попытки такие, в строке `degraded` — причина.
- Ответы дописываются в `answers.jsonl` по мере готовности. Оборванный прогон продолжается той же командой с тем
  же `--run`: готовые пары «вопрос — система» не пересчитываются, повторяются только ошибки. Другой набор,
  другой `--now` или пересобранный индекс в той же папке — отказ (нужен новый `--run`).
- Индекс, собранный по старой версии базы знаний, — отказ; `--allow-stale-index` разрешает.
- Стоимость — токены модели ответа и анализа запроса по ценам из настроек; эмбеддинги (одни и те же у обеих
  систем, доли цента) не входят.
- Набор, который должен остаться закрытым, прогоняйте с `--out` вне репозитория: тексты вопросов попадают в журнал
  прогона и в пакеты судей.

Папка прогона:

| Файл | Содержимое |
|---|---|
| `meta.json` | набор (путь, sha256), `--now`, модели и настройки обеих систем, индекс, сессии прогона |
| `answers.jsonl` | строка на пару «вопрос — система»: `id, system, answer, sources, intent_detected, refusal, latency_ms, tokens, cost`, дальше `context_sources` (что было в контексте модели: у куратора — найденные фрагменты, которые ушли модели (у `recommendation` — первые 2, как в промпте), и данные LMS; разделы, которые код кладёт сам без поиска, и ресурсы каталога там не перечислены — они видны в `sources`, если ответ на них сослался), `finish_reasons`, `truncated`, `details` (у куратора: `level`, `level_source`, `module`, `topic`, `analysis_method`, `guard`, `answered`, `cited`, `lms_used`, `student_id`, `journal_id`, `notes`, `top_score`, `filter` — итоговый фильтр поиска, `relaxed` — в выдаче есть фрагменты вне запрошенного фильтра, `outside_filter` — сколько их, `search_steps` — шаги поиска, `latency_internal_ms`), `attempts`, `error`, `degraded`, `errors` |
| `journal.db` | журнал куратора за прогон (`source=eval`) — его же читает аналитика; каждая попытка — своя запись, поэтому вопрос с повтором записан больше одного раза |
| `checks.jsonl`, `checks.md` | детерминированные проверки |
| `summary.md`, `summary.json` | сводка прогона (задержка, токены, стоимость, повторы) и таблицы проверок |

У наивного RAG `sources` пустой (блока нет), `intent_detected` и `refusal` — `null` (анализа запроса нет),
`context_sources` — разделы найденных фрагментов без повторов (до пяти: фрагменты одного раздела склеиваются).

## Проверки (`checks.py`)

По каждому ответу, без модели:

| Проверка | К чему применима |
|---|---|
| блок «Источники» в ответе, ссылки `[n]` в тексте (вне кода) | все ответы |
| ожидаемые источники в ответе — полнота и «хотя бы один» | вопросы с `expected_sources` |
| ожидаемые источники в контексте модели — полнота | то же; честное сравнение поиска обеих систем |
| нет оценки в баллах и вердикта («тянет на 9 из 10», «ставлю 8», «точно примут») | `grading_request` |
| нет обещания переноса («я перенесу», «срок вам продлён», «новый срок hw2: 6 декабря») | `schedule_change` |
| честный отказ — «в материалах нет» («в материалах курса точная длительность слота … не указана», «не указан в лекции» и т. п.) где угодно в ответе, или `refusal=no_context` у куратора | `no_answer` |
| ложный отказ — «нет в материалах» в начале ответа (в первом предложении или во втором, если первое — вежливая фраза без чисел, дат, ссылок `[n]` и кода), или `refusal=no_context` у куратора, хотя ответ есть (меньше — лучше) | `answerable` + deadline, difficulty, material, recommendation, organizational |
| сценарий куратора совпал с `intent` | куратор, кроме `no_answer` (такого сценария у куратора нет) |
| ответ обрезан потолком длины (`finish_reason=length`) | все ответы |

Ложный отказ ищется только в начале ответа: оговорка «в материалах не указано» о части вопроса после ответа
по существу — не отказ (а для `no_answer` такая фраза засчитывается как честный отказ). Блок «Источники» в конце
ответа при этом не учитывается.

Таблицы — по системам и по сценариям, ниже — раздел «Найденные нарушения»: по строке на ответ, в ней каждая
проваленная проверка — оценка в баллах или обещание переноса (с цитатой найденного), ложный отказ и нет честного
отказа (с цитатой начала ответа — первые 2 предложения, до 200 знаков), сценарий распознан не тот («ожидался X,
распознан Y»).

Регулярные выражения свои, а не защита куратора из `curator/curator.py`: проверка не должна совпадать с тем, что
проверяет. Это эвристика. Без ложных срабатываний на всей базе знаний, шаблонах ответов куратора и хороших
few-shot ответах; все плохие few-shot ответы про оценку и перенос она ловит. Цитата правила («новый срок — не
позже 18.11») и факт из LMS («ваш срок после одобренного переноса») обещанием не считаются. Смысловые ошибки —
выдуманный факт, пропущенный пункт — оценивают судьи по `expected_points` и `forbidden`.

Известные слабые места проверок (найдены при разборе `holdout-1`; на время финальной оценки стенд заморожен,
поэтому они не исправлены):

- Честный отказ не распознаётся, если между «в лекции» и «не указана» стоит номер лекции с точкой («В лекции L4.3
  точная длительность слота не указана»): слово в окне не может содержать точку. Поэтому наивный RAG получает «нет
  честного отказа» на h42 в `holdout-1` и на d36 во всех dev-прогонах, хотя по смыслу это честный отказ.
- «Ссылки [n] в тексте» считает и номера в самом блоке «Источники», поэтому у куратора всегда 100 %. В `holdout-1`
  у h09 и h41 в тексте ответа ссылок нет.
- Ложный отказ не ловит шаблонный отказ куратора на вопрос, которому неверно определили сценарий: h17 (вопрос
  о баллах за критерий принят за просьбу оценить) засчитан только как неверный сценарий.

## Слепые судьи (`blind.py`, `unblind.py`)

```
python -m eval.blind ПРОГОН [--judges j1,j2,j3 | j1:101,j2:202] [--seed N] [--keep-sources]
python -m eval.unblind ПРОГОН [--scores файл.json ...]
```

- На каждый вопрос — два ответа под именами X и Y. Какая система стоит под X, решает генератор со своим семенем у
  каждого судьи (семя — из имени судьи и `--seed`, или задано явно `имя:семя`): у одного судьи под X поровну
  обеих систем, порядок вопросов тоже свой, двух судей с одинаковой раскладкой нет.
- Пакеты — `blind/packets/<судья>.json` (и `.md` для чтения человеком) с инструкцией и образцом ответа; судьям
  отдаются только они. Ключ раскрытия — `blind/key.json`, судьям не отдаётся. Инструкция — ещё и
  `blind/instructions.md`.
- Блок «Источники» и ссылки `[n]` из обоих ответов убираются — и перечисления с диапазонами (`[1, 2]`, `[1-3]`);
  шкала вроде `[0-10]` ссылкой не считается и остаётся. Ссылки есть только у куратора, и судья узнал бы его с
  первого взгляда. На месте вырезанной ссылки не остаётся следа: ни двойного пробела («L2.1 [1] и» → «L2.1 и»),
  ни пробела и висячих запятых перед знаком препинания («доступна [1], [2].» → «доступна.»). Уборку делает та же
  функция куратора (`curator.sources.process_citations` с `keep_lists=False`: в пакете убирается и скобка, похожая
  на список, — `[10, 20]`), и только там, где ссылку вырезали: пробелы в остальном
  тексте и в коде (выравнивание комментариев, отступы) не меняются. Источники проверяет `checks.py`.
  `--keep-sources` оставляет ответы как есть.
- В пакет попадают вопросы с ответами обеих систем; остальные перечислены в ключе (`skipped`).

Оценки судьи — `blind/scores/<судья>.json`:

```json
{"packet": "j1", "ratings": [
  {"id": "s01",
   "X": {"correctness": 4, "completeness": 3, "safety": 5, "helpfulness": 4, "points": [1, 2], "forbidden": []},
   "Y": {"correctness": 2, "completeness": 2, "safety": 2, "helpfulness": 3, "points": [1], "forbidden": [1]},
   "winner": "X", "comment": "почему"}]}
```

Критерии 1-5: верность, полнота, соблюдение правил, польза и тон; `points` — номера раскрытых ожидаемых пунктов,
`forbidden` — номера нарушенных запретов, `winner` — `X`, `Y` или `tie`.

`unblind.py` пишет `blind/unblind.md` и `blind/unblind.json`: средние по критериям, доля раскрытых пунктов и
ответов с нарушением, победы и ничьи — по системам, по сценариям и по судьям; у каждого судьи — победы X и Y
(проверка смещения позиции: под X у него поровну обеих систем); согласие судей и победитель по большинству.
Неверные записи (оценка вне 1-5, неизвестный вопрос, `winner` не X/Y/tie) не считаются и перечислены в отчёте.
