## Цель ДЗ

Пройти полный путь табличного анализа на pandas: прочитать CSV, проверить и очистить данные, посчитать новые
показатели, отобрать и отсортировать строки, сгруппировать продажи и сформулировать выводы с цифрами. Итог работы —
ноутбук, по которому владелец кофейни понял бы, где и что продаётся лучше всего.

## Данные

Файл `coffee_sales.csv` приложен к заданию hw2 в LMS. Это вымышленные продажи сети из трёх кофеен за октябрь 2026
года, около 2 400 строк. Одна строка — одна позиция чека: если гость купил капучино и круассан, у чека две строки
с одним `order_id`. Две одинаковые позиции записываются одной строкой с `quantity = 2`.

| Столбец | Тип | Описание |
|---|---|---|
| `order_id` | целое | номер чека |
| `date` | дата `ГГГГ-ММ-ДД` | день продажи |
| `time` | текст `ЧЧ:ММ` | время чека |
| `store` | текст | точка: «Центр», «Вокзал», «Университет» |
| `product` | текст | позиция меню |
| `category` | текст | «Кофе», «Чай», «Выпечка», «Еда» |
| `size` | текст | объём напитка `S`, `M`, `L`; у выпечки и еды пусто |
| `quantity` | целое | количество в строке |
| `unit_price` | целое | цена за единицу, руб. |
| `payment` | текст | способ оплаты: `card`, `cash`, `sbp` |

Начало файла:

```text
order_id;date;time;store;product;category;size;quantity;unit_price;payment
50001;2026-10-01;07:58;Вокзал;Американо;Кофе;L;1;190;card
50002;2026-10-01;08:05;Центр;Капучино;Кофе;M;1;220;sbp
50002;2026-10-01;08:05;Центр;Круассан;Выпечка;;1;150;sbp
50003;2026-10-01;08:12;Университет;Латте;Кофе;S;2;200;
50004;2026-10-01;09:30;Центр;Чай чёрный;Чай;M;1;160;cash
50004;2026-10-01;09:30;Центр;Чай чёрный;Чай;M;1;160;cash
50005;2026-10-01;13:15;Университет;Сэндвич с курицей;Еда;;1;290;card
50006;2026-10-01;18:40;Вокзал;Раф;Кофе;M;1;260;card
50006;2026-10-01;18:40;Вокзал;Маффин;Выпечка;;0;140;card
```

Особенности файла, с которыми нужно разобраться:

- разделитель — точка с запятой, кодировка UTF-8;
- пустой `size` у выпечки и еды — это нормально, у них нет объёма;
- пустой `payment` — сбой кассы при выгрузке (как в чеке 50003), а продажа при этом была;
- полностью одинаковые строки — дубли выгрузки (как у чека 50004);
- строки с `quantity = 0` — отменённые позиции (маффин в чеке 50006).

## Шаги

### Шаг 1. Загрузка и первый осмотр (L2.1)

```python
import pandas as pd

sales = pd.read_csv("coffee_sales.csv", sep=";", parse_dates=["date"])
print(sales.shape)
sales.info()
sales.head()
```

Проверьте, что столбцов десять, а `date` получил тип `datetime64[ns]`. В markdown-ячейке коротко опишите,
что в данных: сколько строк, за какой период, в каких столбцах есть пропуски.

### Шаг 2. Очистка (L2.2)

1. Посчитайте пропуски: `sales.isna().sum()`.
2. Примите решение по `size` и `payment` и объясните его. Строки с пустым `size` удалять нельзя: пропадут вся
   выпечка и еда. Пустой `payment` удобно заполнить значением `"unknown"`.
3. Удалите полные дубли (`duplicated`, `drop_duplicates`) и строки с `quantity = 0`.
4. Проверьте, что `unit_price` больше нуля во всех строках.
5. Запишите, сколько строк было, сколько стало и почему.

### Шаг 3. Новые столбцы

- `revenue` — выручка строки: `quantity * unit_price`;
- `weekday` — день недели из `date` (`dt.day_of_week`, 0 — понедельник; русские названия можно получить словарём);
- `hour` — час из `time`, например `sales["time"].str[:2].astype(int)`.

Всё считается операциями над столбцами целиком, без циклов `for` по строкам.

### Шаг 4. Фильтрация и сортировка (L2.2)

1. Отберите утренние продажи кофе: `category == "Кофе"` и `hour < 10`. Посчитайте их выручку и долю в выручке
   всей сети.
2. Выведите 10 строк с наибольшей выручкой (`nlargest` или `sort_values`).
3. Отсортируйте очищенную таблицу по `date` и `time`.

### Шаг 5. Группировка и агрегация (L2.3)

1. По каждой точке: выручка, число чеков (`nunique` по `order_id`) и средний чек. Средний чек считается в два
   шага: сумма по каждому чеку, затем среднее по чекам.
2. Топ-5 позиций меню по выручке и топ-5 по проданному количеству.
3. Выручка по дням недели в порядке от понедельника до воскресенья.
4. Сводная таблица «точка × категория» с суммой выручки (`pivot_table`, `fill_value=0`, итоги через `margins=True`).

### Шаг 6. Выводы

В отдельной markdown-ячейке напишите 3-5 выводов с конкретными числами: какая точка приносит больше выручки, какой
день недели самый слабый, что продаётся лучше утром, и одну рекомендацию владельцу. Графики в этом ДЗ
не обязательны и не оцениваются: визуализация — тема модуля 3.

## Частые ошибки

- **Средний чек как среднее по строкам.** `groupby("store")["revenue"].mean()` даёт среднюю позицию, а не средний
  чек. Сначала сложите выручку внутри чека.
- **`dropna()` без аргументов.** Удаляет все строки с пустым `size`, то есть всю выпечку и еду. Указывайте `subset`.
- **Файл прочитан без `sep=";"`.** Вся таблица оказывается в одном столбце.
- **Дата осталась текстом.** Без `parse_dates` или `pd.to_datetime` не работает `dt.day_of_week`.
- **Число чеков посчитано через `count` или `size`.** Это число строк; для чеков нужен `nunique` по `order_id`.
- **Дни недели по алфавиту.** Группировка по русским названиям сортирует их по алфавиту, а не по порядку недели.
  Группируйте по номеру дня, а названия подставляйте после.
- **Ноутбук не запускается с начала.** Ячейки выполнялись вразнобой, и переменная осталась от удалённой ячейки.
  Перед сдачей перезапустите среду и выполните всё заново.
- **Выводы без чисел.** «Центр продаёт больше» не вывод, пока не указано, на сколько.
