# Структура отчёта и выводы

Итоговый проект сдаётся ноутбуком: ссылкой на Google Colab или файлом .ipynb в LMS. Проверяющий читает его
сверху вниз, как статью. Поэтому отчёт должен быть не журналом экспериментов («попробовал так, потом эдак»),
а рассказом: вопрос, данные, что сделали, что получилось, что из этого следует. В лекции разберём скелет отчёта,
оформление таблиц и графиков и то, как писать выводы, которые выдерживают вопросы на защите.

## Скелет отчёта

Заголовки задаются в текстовых (markdown) ячейках ноутбука: строка, начинающаяся с `#`, становится заголовком
первого уровня, с `##` — второго, с `###` — третьего. В Colab и JupyterLab по таким заголовкам строится
оглавление, и проверяющий может сразу перейти к нужному разделу. Рабочая структура отчёта:

- **Заголовок первого уровня** с названием проекта, например: Велопрокат «ВелоГрад»: кто и когда ездит.
  Сразу под ним две строки: **Вопрос** (главный вопрос проекта) и **Коротко** (2-3 предложения с главными
  цифрами; пишутся в самом конце, но ставятся в начало). Дальше идут разделы второго уровня.
- **1. Данные**: источник, период, число строк, описание колонок и единиц измерения.
- **2. Подготовка данных**: что удалили или исправили, почему и сколько строк осталось.
- **3. Анализ**: подразделы 3.1, 3.2, 3.3, по одному на подвопрос, например «Время суток», «Длительность
  и стоимость», «Погода».
- **4. Выводы**: ответ на главный вопрос.
- **5. Ограничения и что дальше**.

Раздел «Коротко» нужен для читателя, у которого есть одна минута. Подразделы анализа повторяют подвопросы из
L4.1: один подвопрос, одна таблица или график, один промежуточный вывод. Код и текст чередуются: перед ячейкой
с кодом одна фраза о том, что сейчас посчитаем, после неё короткий комментарий к результату. Служебные ячейки
(импорты, настройки отображения) соберите в самом начале, чтобы они не разрывали рассказ.

## Подготовка данных: функции и счёт строк

Очистку удобно собрать в функцию. Тогда её легко перезапустить, а решения видны в одном месте:

```python
import pandas as pd

def load_trips(path: str) -> pd.DataFrame:
    return pd.read_csv(path, parse_dates=["start_time", "end_time"])

def clean_trips(raw: pd.DataFrame) -> pd.DataFrame:
    df = raw.drop_duplicates(subset="trip_id").copy()
    df["district"] = df["district"].str.strip().str.capitalize()
    # больше 600 минут (10 часов) считаем незакрытой арендой
    df = df[df["duration_min"].between(1, 600)]
    return df

raw = load_trips("velograd_trips_2026.csv")
trips = clean_trips(raw)
print(f"Удалено строк: {len(raw) - len(trips)} из {len(raw)}")
```

Под ячейкой напишите текстом, что и почему удалено: «Удалили 60 повторных строк и 40 поездок с отрицательной
длительностью или длительностью больше 10 часов, всего 0,8% данных». Проверяющему важно видеть, что очистка не изменила
картину целиком.

## Таблица, которая отвечает на подвопрос

Именованная агрегация даёт колонкам понятные имена сразу:

```python
summary = (
    trips.groupby("user_type")
    .agg(
        trips_count=("trip_id", "count"),
        median_minutes=("duration_min", "median"),
        revenue_rub=("price_rub", "sum"),
    )
    .assign(revenue_share=lambda t: (t["revenue_rub"] / t["revenue_rub"].sum()).round(3))
    .sort_values("revenue_rub", ascending=False)
)
summary
```

Колонка `revenue_share` показывает долю выручки каждой группы. В учебном наборе такая таблица сразу даёт
сюжет: абоненты совершают больше половины поездок, но почти не платят за сами поездки, потому что первые
30 минут у них бесплатны. Показывайте итоговые таблицы, а не весь `DataFrame`: вывод на тысячи строк никто
не читает. Для просмотра хватит `head()` или `sample(5)`.

## График с выводом в заголовке

Заголовок графика может сразу говорить, что на нём видно (приём из L3.3):

```python
import matplotlib.pyplot as plt

by_hour = pd.crosstab(trips["start_time"].dt.hour, trips["user_type"])

fig, ax = plt.subplots(figsize=(9, 4))
by_hour.plot(ax=ax, marker="o")
ax.set(
    title="Абоненты ездят в часы пик, разовые пользователи днём",
    xlabel="Час начала поездки",
    ylabel="Число поездок",
)
ax.legend(title="Тип пользователя")
fig.tight_layout()
plt.show()
```

`pd.crosstab` считает, сколько поездок пришлось на каждую пару «час × тип пользователя»: строки — часы,
колонки — типы. Метод `.plot()` у такой таблицы рисует по линии на колонку, а легенду берёт из названий колонок.
Если заголовок-вывод не получается сформулировать, это сигнал: график пока ничего не показывает, и его стоит
заменить или убрать.

## Как писать выводы

Рабочая формула вывода: **факт с числом → что это значит → что можно сделать → оговорка.**

- Слабо: «Абоненты ездят по-другому». Непонятно, как именно и насколько.
- Слабо: «На графике видно, что линии разные». Это пересказ графика, а не вывод.
- Сильно: «59% поездок абонентов начинаются в 7-8 и 17-18 часов, у разовых пользователей таких поездок 15%.
  Похоже, абонемент используют для дороги на работу. Утром у станций в центре стоит держать запас велосипедов.
  Оговорка: данные только за май-октябрь».

Числа в выводах берите из кода, а не переписывайте руками: после повторной очистки они могут измениться.

```python
is_peak = trips["start_time"].dt.hour.isin([7, 8, 17, 18])
for user_type, share in is_peak.groupby(trips["user_type"]).mean().items():
    print(f"{user_type}: в часы пик {share:.0%} поездок")
```

## Ограничения и что дальше

Раздел ограничений не признак слабой работы, а признак честной. Типичные пункты: короткий период данных;
выборка неполная (в прокате видны только состоявшиеся поездки); связь не доказывает причину; очистка убрала
часть строк. «Что дальше» — 1-2 идеи: какие данные добавить и какой вопрос задать следующим.

## Частые ошибки

- **Вывод не отвечает на вопрос.** Вопрос был про абонентов, а выводы про погоду.
- **Числа без единиц и базы.** «Выросло на 12» — чего, относительно чего?
- **Ноутбук не выполняется сверху вниз.** Переменная осталась из удалённой ячейки. Перед сдачей перезапустите
  ядро и выполните все ячейки: в Colab меню Runtime («Среда выполнения») → Restart session and run all,
  в JupyterLab Kernel → Restart Kernel and Run All Cells.
- **`df.corr()` падает с ValueError.** В pandas 2.x по умолчанию `numeric_only=False`, и текстовые колонки
  вызывают ошибку. Пишите `df.corr(numeric_only=True)`.
- **Корреляция выдана за причину.** «Тепло, поэтому ездят дольше» без оговорок.
- **Графики без подписей осей и единиц** или с подписями по умолчанию вроде `duration_min`.

## Для продвинутых

- Покажите неопределённость. Бутстреп-интервал для медианы считается в несколько строк:

```python
import numpy as np

rng = np.random.default_rng(42)
minutes = trips.loc[trips["user_type"] == "casual", "duration_min"].to_numpy()
medians = [np.median(rng.choice(minutes, size=len(minutes))) for _ in range(1000)]
low, high = np.percentile(medians, [2.5, 97.5])
print(f"Медиана {np.median(minutes):.0f} мин, 95% интервал {low:.0f}-{high:.0f} мин")
```

- Говорите о размере эффекта, а не только о направлении: «медиана в 2,3 раза больше» информативнее, чем «больше».
- Зафиксируйте окружение: выведите `pd.__version__` в начале ноутбука, задайте seed для всего случайного.
- Экспортируйте отчёт в HTML для читателей без Python: `jupyter nbconvert --to html report.ipynb`.
