# Как выбрать датасет и поставить вопрос

Модуль 4 (14-27 декабря) целиком посвящён итоговому проекту. В нём вы сами проходите путь, который в модулях 1-3
шёл по частям: вопрос, данные, очистка, таблицы, графики, выводы. Эта лекция про первый и самый недооценённый шаг:
выбрать данные и сформулировать вопрос так, чтобы на него можно было ответить за две недели.

## Почему начинать с вопроса, а не с данных

Анализ без вопроса превращается в альбом графиков: «вот распределение цены, вот число заказов по дням». Каждый
график верный, но читатель не понимает, что из них следует. Вопрос работает как фильтр. Он подсказывает, какие
колонки нужны, какую метрику считать (сумму, медиану, долю), в каком разрезе (по дням, районам, типам клиентов)
и какой график выбрать. Если вопроса нет, на защите почти наверняка спросят: «А зачем вы это считали?»

## Где взять данные

- **Набор «ВелоГрад» из методички guide-4.** Вымышленные поездки городского велопроката за май-октябрь 2026 года,
  около 12 000 строк. Это базовый вариант: данные уже проверены на пригодность, и в них специально оставлены
  пропуски, дубли и ошибки, чтобы было что чистить.
- **Kaggle Datasets** (kaggle.com/datasets). У каждого набора есть страница с описанием, лицензией и обсуждением.
- **UCI Machine Learning Repository** (archive.ics.uci.edu): классические наборы с подробным описанием признаков.
- **Порталы открытых данных** городов и ведомств: статистика, транспорт, экология.
- **Учебные наборы seaborn**: `sns.load_dataset("tips")` скачивает таблицу из репозитория seaborn-data на GitHub,
  поэтому нужен интернет. Их удобно брать для тренировки, но для проекта лучше найти что-то менее известное.

## Чек-лист хорошего датасета

| Критерий | Зачем | Как проверить |
|---|---|---|
| Известны источник и лицензия | Данные можно законно использовать и показывать | Страница набора, раздел License |
| Есть описание колонок | Понятны единицы измерения и смысл значений | Файл README или описание на сайте |
| Не меньше 500 строк и 5 колонок | Есть что группировать и сравнивать | `df.shape` |
| Есть числовые и категориальные колонки, желательно дата | Можно строить разные типы графиков | `df.info()` |
| Нет персональных данных | ФИО, телефоны и адреса в учебном проекте не нужны | Просмотреть `df.head()` и названия колонок |
| Пропусков не больше, чем полезных значений | После очистки останутся данные | `df.isna().mean()` |

Минимальный размер (500 строк, 5 колонок) совпадает с требованием к своему датасету из методички guide-4.

## Первичный осмотр за пять минут

Прежде чем влюбиться в датасет, загрузите его и посмотрите на структуру:

```python
import pandas as pd

df = pd.read_csv("velograd_trips_2026.csv", parse_dates=["start_time", "end_time"])

print(df.shape)  # (число строк, число колонок)
df.info()        # типы колонок и число непустых значений
df.head()
```

Удобно собрать короткую сводку по всем колонкам сразу:

```python
def quick_profile(df: pd.DataFrame) -> pd.DataFrame:
    """Тип, доля пропусков и число уникальных значений по каждой колонке."""
    return pd.DataFrame({
        "dtype": df.dtypes.astype(str),
        "missing_share": df.isna().mean().round(3),
        "n_unique": df.nunique(),
    })

print(quick_profile(df))
print("Повторов trip_id:", df["trip_id"].duplicated().sum())
```

На что смотреть: дата должна иметь тип `datetime64[ns]`, а не `object` (иначе вы забыли `parse_dates`);
у идентификатора число уникальных значений должно совпадать с числом строк; категориальные колонки с сотнями
уникальных значений неудобны для графиков.

## Как сформулировать вопрос

Двигайтесь по лестнице: тема → вопрос → метрика → разрез → график. Например: велопрокат → «чем поездки абонентов
отличаются от разовых?» → число поездок и медианная длительность → по часу начала и типу пользователя →
линейный график по часам.

| Слабая формулировка | Что не так | Сильная формулировка |
|---|---|---|
| «Проанализировать велопрокат» | Это тема, а не вопрос | «Чем поездки абонентов отличаются от разовых по времени суток и длительности?» |
| «Почему люди выбирают велосипед?» | В данных нет мотивов людей | «В какие часы будних дней начинается больше всего поездок?» |
| «Доказать, что дождь снижает выручку» | Ответ решён заранее | «Как меняются число и длительность поездок в дождливые часы?» |
| «Какие станции закрыть?» | Решение не следует из одних поездок | «На каких станциях начинается меньше всего поездок?» |

Хороший итог этого шага: один главный вопрос и 2-3 подвопроса. Каждый подвопрос потом станет отдельным разделом
отчёта (см. L4.2).

## Проверяем, что на вопрос можно ответить

Запишите для каждого подвопроса колонки, без которых ответа не будет, и проверьте их наличие кодом:

```python
question_columns = {
    "Влияет ли дождь на длительность поездки?": ["is_rain", "duration_min"],
    "Когда абоненты ездят чаще разовых пользователей?": ["user_type", "start_time"],
    "Какой район приносит больше выручки?": ["district", "price_rub"],
}
for question, cols in question_columns.items():
    missing = [c for c in cols if c not in df.columns]
    print("OK " if not missing else "НЕТ", question, missing or "")
```

Затем сделайте одну черновую таблицу на подвопрос. Если она получается, вопрос выполним:

```python
bands = pd.cut(
    df["temperature_c"],
    bins=[-10, 10, 20, 40],
    labels=["до 10 °C", "10-20 °C", "выше 20 °C"],
)
print(df.groupby(bands, observed=True)["duration_min"].median())
print("Поездок без температуры:", bands.isna().sum())
```

Обратите внимание: строки с пропуском температуры в группы не попадают. Это нормально, но о таком нужно
написать в отчёте.

## Частые ошибки

- **Слишком большой файл.** Набор на несколько гигабайт не поместится в память бесплатного Colab. Для учебного
  проекта хватит десятков тысяч строк.
- **Вопрос о причинах при данных о совпадениях.** Из таблицы поездок видно, что в дождь ездят меньше, но не видно
  почему. Формулируйте вопрос как «как связано», а не «почему».
- **Не прочитали описание колонок.** Минуты путают с секундами, время UTC с местным, рубли с тысячами рублей.
- **Дата осталась строкой.** Без `parse_dates` (или `pd.to_datetime`) не работают `.dt.hour` и сортировка по времени.
- **Данные без источника.** Таблицу «из интернета» без лицензии и описания на защите не объяснить.
- **Вопрос меняют в последние дни.** Менять вопрос можно, но лучше в первую неделю модуля (до 20 декабря),
  иначе не хватит времени на выводы.

## Для продвинутых

- Составьте словарь данных: колонка, тип, единицы, допустимые значения, источник. Это сразу готовый раздел отчёта.
- Оцените память: `df.memory_usage(deep=True).sum() / 1024**2` даёт размер в мегабайтах. Повторяющиеся строки
  (район, тип велосипеда) хранятся экономнее как `astype("category")`.
- Для больших файлов читайте только нужное: `pd.read_csv(path, usecols=[...], dtype={...})`, а для первого
  взгляда хватит `nrows=1000`.
- Запишите гипотезы до того, как смотреть на графики. Гипотеза, придуманная после результата (HARKing), почти
  всегда «подтверждается».
- Подумайте о смещении выборки: в данных проката есть только состоявшиеся поездки. Спрос в часы, когда на станции
  не было велосипедов, в таблицу не попал.
- Проверяйте выводы в разрезах: общий тренд может развернуться внутри групп (парадокс Симпсона).
